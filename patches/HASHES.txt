# Offline replay of the SAME 6-case rollout traces (not a new live run)
# tested whether any other transform of the per-round reading separates
# the cases: p_yes>p_no as a boolean fed through the same fast/slow EMA
# (worse than raw magnitude -- case_004, the one case that needed help,
# still has the smallest gap of all 6, and the two clean cases alone span

# simple-moving-average of raw p_yes at window sizes 10/20/40/80 (case_004
# has the smallest gap at every window size), and p_hedge-p_confident
# per-round (degenerate -- ~100% positive at threshold 0.0, collapses to
# ~0% by 0.02, no usable per-round cutoff; the hedge/confident signal is
# real only as a whole-run aggregate mean, never validated per-round).
# Conclusion: no reshaping of this reading, at any granularity, separates
# "needs it" from "doesn't" -- chasing another variant was not going to
# fix that.
#
# What changed instead is the COST of a false positive, not the
# discrimination. The old mechanism, once triggered, forced a fixed
# unrelated 24-token redirect phrase into the real committed output --
# catastrophic when wrong (3 of 6 cases in the rollout had a correct
# answer degraded to wrong/no_answer by exactly this). The new mechanism
# computes a per-round score (p_yes - p_no, no EMA, no trend, nothing
# persisted across rounds) and, when it crosses
# SPEC_CASC_TOK_FREE_JUDGMENT_REJECT_THRESHOLD (default 0.08, picked from
# real-trace resample-rate calibration, not a proof of separation), bans
# ONLY the single last real drafted token this round (same
# ban-a-specific-token-and-renormalize mechanism already used for the
# criterion token, NOT a forced pattern) -- rejection sampling's own
# residual-resample then draws a fresh, genuinely target-favored
# alternative at that one position. A false positive now costs one
# resampled token, not a derailing paragraph. This also deletes an entire
# class of bug the old mechanism needed two separate fixes for (the
# double-pivot-injection / natural-final-open-detection bugs documented
# below): there is no multi-round forced pattern to track anymore, so
# there is nothing to accidentally re-trigger inside the model's own
# final answer. All EMA/mode-state-machine code, PIVOT_PATTERN,
# FINAL_OPEN_PATTERN, and their two knob files (PIVOT_MARGIN,
# PIVOT_FINAL_THRESHOLD) are removed; replaced by the single
# REJECT_THRESHOLD knob. Not yet validated on a live rollout -- unit and
