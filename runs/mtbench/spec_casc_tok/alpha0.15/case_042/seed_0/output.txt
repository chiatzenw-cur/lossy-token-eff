We are given two sorted arrays `A` and `B` (they may have different lengths).  
The task is to return the median of the *combined* array without actually merging
the two arrays and using only a constant amount of extra memory.

The median of an array of length `L` is

* the middle element if `L` is odd  
* the average of the two middle elements if `L` is even

So we only need to know the elements that land at the two middle positions after
the arrays are merged.  
Because the arrays are sorted we can walk through them with two pointers, just
as in the merge step of merge‑sort, and keep track of the current **index** in
the merged order.  
When that index reaches the required middle positions we have found the median
components.

The algorithm runs in  
*`O(m + n)` time* (we inspect each element once) and  
*`O(1)` extra space* (just a handful of indices and variables).

---

## Algorithm

```
function medianOfTwoSortedArrays(A, B):
    m = len(A)
    n = len(B)
    total = m + n

    // Positions of the middle elements in the merged array
    mid1 = (total - 1) // 2        // first middle (0‑based)
    mid2 = total // 2              // second middle (0‑based)

    i = 0          // pointer in A
    j = 0          // pointer in B
    count = 0      // number of elements already merged
    m1 = 0         // value at mid1
    m2 = 0         // value at mid2

    while i < m or j < n:
        // Pick the next smallest element
        if j == n or (i < m and A[i] <= B[j]):
            val = A[i]
            i += 1
        else:
            val = B[j]
            j += 1

        if count == mid1:
            m1 = val
        if count == mid2:
            m2 = val
            break        // both middle elements found

        count += 1

    // Compute the median
    if total % 2 == 1:
        return m1               // only one middle element needed
    else:
        return (m1 + m2) / 2.0  // average of the two middle elements
```

**Why it works**

* The two pointers always point to the smallest unused elements in the two
  arrays, so the variable `val` is the *next* element in the merged order.
* `count` is exactly the index of that element in the merged array.
* When `count` equals `mid1` or `mid2` we have located the two middle
  elements.
* We stop as soon as both middle elements are found – no extra work is
  necessary.

## Correctness Proof  

We prove that the algorithm returns the correct median.

### Lemma 1  
During the loop, before any iteration finishes, `count` equals the number of
elements already taken from the two arrays.

*Proof.*  
Initially `count = 0`; no elements have been taken.  
Each iteration selects exactly one element (`val`) and then increments
`count` (unless the loop terminates early).  
Thus after the *k*-th iteration `count = k`. ∎

### Lemma 2  
When the loop terminates, `m1` equals the element at global index `mid1`
and `m2` equals the element at global index `mid2` in the merged array.

*Proof.*  
Consider the moment when `count == mid1`.  
By Lemma&nbsp;1, exactly `mid1` elements have already been taken, so the
current element `val` is the element at index `mid1`.  
The algorithm stores it in `m1`.  
A similar argument for when `count == mid2` shows that `m2` is the element
at index `mid2`.  
The loop stops immediately after storing `m2`, so the stored values are
exactly the two middle elements. ∎

### Lemma 3  
If `total` is odd, the median of the combined array equals `m1`.

*Proof.*  
For odd `total`, we have `mid1 == mid2`.  
By Lemma&nbsp;2 both `m1` and `m2` are the same element – the single middle
element of the merged array.  
The median of an odd‑length sorted array is that middle element, so the
algorithm returns the correct median. ∎

### Lemma 4  
If `total` is even, the median of the combined array equals `(m1 + m2)/2`.

*Proof.*  
For even `total`, the two middle positions are `mid1` and `mid2`.  
By Lemma&nbsp;2, `m1` and `m2` are the elements at those positions.  
The definition of median for an even‑length array is the average of the
two middle elements, so the algorithm returns the correct median. ∎

### Theorem  
The algorithm always returns the median of the two sorted arrays.

*Proof.*  
All possibilities for `total` (odd or even) are covered by Lemma&nbsp;3 and
Lemma&nbsp;4, which together establish correctness. ∎

## Complexity Analysis

Let `m = len(A)` and `n = len(B)`.

* **Time** – Each element of `A` and `B` is examined at most once, so the
  running time is `O(m + n)`, i.e. `O(n)` if `n` denotes the total number of
  elements.

* **Space** – Only a constant number of integer variables are used,
  regardless of the input size.  
  Hence the extra space is `O(1)`.

def median_of_two_sorted_arrays(A, B):
    """
    Return the median of the two sorted arrays A and B.
    Works in O(len(A) + len(B)) time and O(1) extra space.
    """
    m, n = len(A), len(B)
    total = m + n

    # Indices of the middle elements (0‑based)
    mid1 = (total - 1) // 2
    mid2 = total // 2

    i = j = 0          # pointers into A and B
    count = 0          # how many elements have been merged so far
    m1 = m2 = 0        # will hold the two middle values

    while i < m or j < n:
        # Pick the next smallest element
        if j == n or (i < m and A[i] <= B[j]):
            val = A[i]
            i += 1
        else:
            val = B[j]
            j += 1

        if count == mid1:
            m1 = val
        if count == mid2:
            m2 = val
            break          # we have both middle elements

        count += 1

    # Compute the median
    if total % 2 == 1:
        return float(m1)               # the single middle element
    else:
        return (m1 + m2) / 2.0          # average of the two middle elements
