A *full* (or *proper*) binary tree is one in which every internal node has **exactly two** children.  
If a full binary tree has `n` vertices, then `n` must be odd – a full binary tree always has

```
#internal nodes  =   (n – 1) / 2
#leaves          =   (n + 1) / 2
```

The number of full binary trees with `k` internal nodes is the `k`‑th Catalan number

```
C_k = 1/(k+1) * binom(2k, k)
```

Therefore

```
B_n = 0                           if n is even
B_{2k+1} = C_k   (k = (n-1)/2)     if n is odd
```

Below we implement both an **iterative Catalan‑number** approach and a **direct DP over odd indices**.  
Both versions run in `O(n²)` time and `O(n)` space (the loops only touch odd indices).

## 1. Python implementation

```python
from __future__ import annotations
from math import comb
from functools import lru_cache

# ------------------------------------------------------------------
# 1.  Direct Catalan closed‑form (requires the math.comb function)
# ------------------------------------------------------------------
def B_closed_form(n: int) -> int:
    """
    Return the number of full binary trees with n vertices.
    Uses the closed‑form Catalan number:
        B_{2k+1} = C_k = binom(2k, k) // (k+1)
    """
    if n % 2 == 0:                 # even number of vertices -> impossible
        return 0
    k = (n - 1) // 2
    return comb(2 * k, k) // (k + 1)


# ------------------------------------------------------------------
# 2.  Recursive DP with memoisation (cache)
# ------------------------------------------------------------------
@lru_cache(maxsize=None)
def B_recursive(n: int) -> int:
    """
    B_n = 0 if n is even
    B_1 = 1
    For n > 1 (odd) :  B_n = Σ_{i=1}^{n-2, i odd} B_i * B_{n-1-i}
    """
    if n % 2 == 0:
        return 0
    if n == 1:
        return 1
    total = 0
    for left in range(1, n - 1, 2):  # left subtree size (odd)
        right = n - 1 - left
        total += B_recursive(left) * B_recursive(right)
    return total


# ------------------------------------------------------------------
# 3.  Iterative DP over all odd indices (no recursion)
# ------------------------------------------------------------------
def B_dp(n: int) -> int:
    """
    Bottom‑up DP that fills dp[odd] = number of full binary trees with that many vertices.
    Complexity: O(n²) time, O(n) space.
    """
    if n % 2 == 0:
        return 0
    dp = [0] * (n + 1)
    dp[1] = 1  # base case

    for nodes in range(3, n + 1, 2):  # only odd indices
        total = 0
        for left in range(1, nodes - 1, 2):  # left subtree size
            right = nodes - 1 - left
            total += dp[left] * dp[right]
        dp[nodes] = total

    return dp[n]


# ------------------------------------------------------------------
# 4.  Quick tests / sanity checks
# ------------------------------------------------------------------
if __name__ == "__main__":
    # Known values (Catalan numbers)
    known = {1: 1, 3: 1, 5: 2, 7: 5, 9: 14, 11: 42, 13: 132}

        assert B_recursive(n) == expected
        assert B_dp(n) == expected
    print("All tests passed – B_n works!")
```

### How the code works

| Function        | What it does                                   | Complexity |
|-----------------|------------------------------------------------|------------|
| `B_closed_form` | Uses the closed‑form Catalan formula. Returns 0 for even `n`. | `O(1)` (apart from the bigint operations) |
| `B_recursive`   | Recursively applies the recurrence `B_n = Σ B_i * B_{n-1-i}` on odd `i`. Memoised with `lru_cache`. | `O(n²)` in the worst case |
| `B_dp`          | Same recurrence, but bottom‑up. Only odd indices are filled. | `O(n²)` time, `O(n)` space |

## 2. Why the recurrence works

A full binary tree with `n` vertices (`n` odd) has a root and two sub‑trees.  
If the left subtree has `i` vertices (odd), the right subtree must have `n-1-i` vertices (also odd).  
Each subtree can be chosen independently, so the total number is the product of the counts for the two sub‑trees.  
Summing over all possible odd `i` gives the recurrence.

---

## 3. Complexity for large `n`

- **Catalan closed form** scales nicely for *very* large `n` because it uses only one binomial coefficient and a division.  
- **Recursive / DP** versions are convenient for moderate values (e.g. `n <= 10⁴`) and are simple to understand / modify.
