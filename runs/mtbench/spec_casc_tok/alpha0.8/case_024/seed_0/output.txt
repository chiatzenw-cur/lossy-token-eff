## 1.  Idea

1. **Sort the two arrays in‑place** – sorting can be done with the language’s built‑in `sort()` (quicksort, heapsort, etc.) which works in‑place.  
2. **Two‑pointer scan** – after sorting, scan the arrays from left to right with two indices (`i` and `j`).  
   * If `arr1[i]` == `arr2[j]` – the value is common, print it (or process it) and advance both indices.  
   * If `arr1[i]` < `arr2[j]` – advance `i` (the smaller element cannot match anything later in `arr2`).  
   * Else (`arr1[i]` > `arr2[j]`) – advance `j`.

Because the arrays are sorted, this “merge” traversal visits every element at most once and therefore produces the intersection in linear time after sorting.

---

## 2.  Algorithm (pseudo‑code)

```
procedure print_common_elements(arr1, arr2):
    sort(arr1)          // in‑place
    sort(arr2)          // in‑place
    i ← 0
    j ← 0
    while i < len(arr1) and j < len(arr2):
        if arr1[i] == arr2[j]:
            print(arr1[i])         // or store/return it
            i ← i + 1
            j ← j + 1
        else if arr1[i] < arr2[j]:
            i ← i + 1
        else:
            j ← j + 1
```

No additional data structures are used – only the two indices and the two input arrays themselves.

## 3.  Correctness Proof

We prove that the algorithm outputs exactly the intersection of the two input arrays.

### Lemma 1  
During the execution, `i` and `j` never move backward; they only increase or stay the same.

*Proof.*  
In the algorithm, `i` and `j` are increased by `1` in every branch of the `while` loop and never decreased. ∎

### Lemma 2  
If `arr1[i] == arr2[j]` at some iteration, the algorithm prints that value and it is indeed a common element of the two arrays.

*Proof.*  
Equality guarantees that the same value occurs in both arrays. Printing it outputs a common element. ∎

### Lemma 3  
If there exists a common element `x` that is **not** printed by the algorithm, then `x` either appears in `arr1` or `arr2` but not both.

*Proof.*  
Suppose for contradiction that `x` is in both arrays but not printed.  
Let `i₀` be the index of `x` in `arr1` (the smallest such index) and `j₀` the index of `x` in `arr2`.  
During the scan, when the algorithm reaches indices `i₀` and `j₀`, the following cannot happen:

1. `arr1[i₀] == arr2[j₀]` – would have been printed (Lemma 2).  
2. `arr1[i₀] < arr2[j₀]` – then `arr1[i₀]` would be smaller than `x`, contradicting minimality of `i₀`.  
3. `arr1[i₀] > arr2[j₀]` – symmetric contradiction.

Hence our assumption is false; every common element is printed. ∎

### Theorem  
The algorithm outputs **exactly** the intersection of the two arrays.

*Proof.*  
By Lemma 2, every printed element is common.  
By Lemma 3, every common element is printed.  
Thus the sets of printed elements and the true intersection are identical. ∎

## 5.  Reference Implementation (Python)

```python
def print_common_elements(arr1, arr2):
    """
    Prints the elements that appear in both arr1 and arr2.
    Modifies the input arrays by sorting them in place.
    No additional data structures are allocated.
    """
    arr1.sort()          # in‑place sort
    arr2.sort()          # in‑place sort

    i = j = 0
    while i < len(arr1) and j < len(arr2):
        if arr1[i] == arr2[j]:
            print(arr1[i], end=' ')
            i += 1
            j += 1
        elif arr1[i] < arr2[j]:
            i += 1
        else:   # arr1[i] > arr2[j]
            j += 1

# Example usage:
if __name__ == "__main__":
    a = [4, 9, 5, 12, 7, 4]
    b = [9, 0, 5, 12, 7, 0, 6]
    print("Common elements:")
    print_common_elements(a, b)
```

```
9 5 12 7 
```

### Alternative: Pure Nested Loops (Unsorted)

If you cannot sort the arrays (e.g., because the input must remain unchanged), you can still do it in `O(n * m)` time:

```python
def print_common_elements_brute(a, b):
    for x in a:
        for y in b:
            if x == y:
                print(x, end=' ')
                break
```

This uses only the two loop variables as extra memory, but it scales poorly for large arrays.
