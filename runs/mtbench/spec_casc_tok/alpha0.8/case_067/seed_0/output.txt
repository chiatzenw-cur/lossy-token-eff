For a full binary tree every internal node has exactly two children.  
Let  

* `i` – number of internal nodes  
* `l` – number of leaves  

For a full binary tree  

```
l = i + 1          (one extra leaf for every internal node)
n = i + l = 2i + 1
```

So **`n` must be odd**.  
If we set  

```
k = (n - 1) / 2          (k = number of internal nodes)
```

then the number of full binary trees with `n` vertices is the same as the
number of full binary trees with `k` internal nodes – that is the **Catalan
number** `C_k`.

```
          B_n = 0                     if n is even
          B_n = C_k (k = (n-1)/2)     if n is odd
```

`C_k` can be computed

* recursively: `C_k = Σ_{i=0}^{k-1} C_i * C_{k-1-i}`
* or directly with the closed‑form formula  

  `C_k = binom(2k, k) / (k+1)`  

  (Python’s `math.comb` implements the binomial coefficient exactly).

Below is a ready‑to‑run Python implementation that uses the closed‑form
formula for **O(1)** computation per call (beyond the cost of the
binomial coefficient).  
(If you prefer to build the sequence once up to a maximum `n`, a simple
dynamic‑programming loop is just a few lines.)

```python
import math
from functools import lru_cache

def full_binary_tree_count(n: int) -> int:
    """
    Return the number of full binary trees with exactly n vertices.

    Parameters
    ----------
    n : int
        Number of vertices.  Must be a non‑negative integer.

    Returns
    -------
    int
        Number of full binary trees.  Zero for even n.

    Examples
    --------
    >>> full_binary_tree_count(1)
    1                 # single node
    >>> full_binary_tree_count(3)
    1                 # root + two leaves
    >>> full_binary_tree_count(5)
    2                 # two different shapes
    >>> full_binary_tree_count(7)
    5                 # Catalan number C_3
    >>> full_binary_tree_count(8)
    0                 # impossible for a full binary tree
    """
    if n < 0:
        raise ValueError("n must be non‑negative")
    if n % 2 == 0:          # even number of vertices → impossible
        return 0

    k = (n - 1) // 2        # number of internal nodes
    # Catalan number C_k = binom(2k, k) // (k+1)
    return math.comb(2 * k, k) // (k + 1)

# -------------------- Alternative DP implementation --------------------
@lru_cache(maxsize=None)
def full_binary_tree_count_dp(n: int) -> int:
    """Same as above but computed via dynamic programming."""
    if n < 0:
        raise ValueError("n must be non‑negative")
    if n % 2 == 0:
        return 0
    if n == 1:
        return 1
    # recurrence: B_n = Σ_{i=1,3,5,...} B_i * B_{n-i-1}
    total = 0
    for left in range(1, n, 2):            # left subtree size
        right = n - left - 1
        total += full_binary_tree_count_dp(left) * full_binary_tree_count_dp(right)
    return total

# -------------------- Quick test --------------------
if __name__ == "__main__":
    for n in range(1, 12):
        print(f"B_{n} = {full_binary_tree_count(n)}")
```

### Complexity

* **Closed‑form**: `O(1)` time, `O(1)` memory (aside from the binomial
  coefficient calculation).  
  (Python’s `math.comb` runs in `O(k)` where `k = (n-1)/2`.)

* **DP recurrence**: `O(n²)` time, `O(n)` memory (the recursion depth is
  `O(n)`).

Either approach is perfectly fine for the “small‑to‑medium” `n` that
usually appears in interviews or coding contests.
