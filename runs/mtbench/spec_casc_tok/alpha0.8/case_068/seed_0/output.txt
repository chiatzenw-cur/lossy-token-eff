The two input lists are already sorted.  
If we scan both lists simultaneously, we can always know which of the two
next‑smallest elements is the current minimum.  
By discarding the smaller element and moving the corresponding pointer, we
“consume” one element from the union.  
After we have discarded *k–1* elements, the next element we pick is the
*k*‑th smallest of the whole union.

This is a classic “two‑pointer” merge‑step that costs only **O(k)** time
and **O(1)** extra memory.  
In the worst case, when `k = m + n` (i.e., we want the last element),
the algorithm runs in **O(m + n)** time – still linear in the input size.

### Algorithm (Python)

```python
def kth_smallest(a, b, k):
    """
    Return the k‑th smallest element in the union of two sorted lists a and b.
    k is 1‑based: k = 1 returns the smallest element.
    Preconditions:
        - a and b are sorted in non‑decreasing order.
        - 1 <= k <= len(a) + len(b)
    Complexity: O(k) time, O(1) space.
    """
    i, j = 0, 0          # indices in a and b
    # Consume k−1 elements (the k‑th will be the answer)
    while k > 1 and i < len(a) and j < len(b):
        if a[i] < b[j]:
            i += 1
        else:
            j += 1
        k -= 1

    # If we ran out of elements in one list, the answer is in the other
    if i == len(a):
        return b[j + k - 1]      # j is the first unconsumed element
    if j == len(b):
        return a[i + k - 1]

    # Both lists still have elements; take the min of the two front elements
    return a[i] if a[i] < b[j] else b[j]
```

### Correctness Proof

We prove that the algorithm returns the **k**‑th smallest element.

*Let* `S = a ∪ b` be the multiset of all elements from both lists, sorted
in non‑decreasing order.  
Let `|S| = m + n`.

1. **Invariant**:  
   After each iteration of the `while` loop, the following holds:
   - We have discarded exactly `k₀` elements from the front of `S`,
     where `k₀` is the initial value of `k` minus the current `k`.
   - The remaining elements are still the first `|S| - k₀` elements of `S`.

   *Proof of Invariant*:  
   Initially no element has been discarded, so the invariant holds.
   In each iteration we compare `a[i]` and `b[j]`.  
   Because `a` and `b` are sorted, the smaller of the two is the smallest
   element among all remaining elements.  
   We discard that element (by incrementing the corresponding index) and
   decrement `k`.  
   Thus exactly one element is removed from the front of `S` and the
   invariant holds for the next iteration.

2. **Termination**:  
   The loop stops when `k == 1` (i.e., we have discarded `k₀ - 1` elements)
   or when one list is exhausted.  
   In either case, the remaining elements are exactly the first `k₀`
   elements of `S`.

3. **Result**:  
   *Case 1*: `k == 1`  
   The next element we pick is the smallest among the two current front
   elements (`a[i]` and `b[j]`).  
   By the invariant, all `k₀ - 1` smaller elements have already been
   discarded, so this element is the `k₀`‑th smallest.

   *Case 2*: one list is exhausted  
   Suppose `a` is exhausted (`i == len(a)`).  
   All elements of `a` are already in the first `k₀ - 1` positions of `S`.  
   The remaining elements are `b[j], b[j+1], …`.  
   The `k`‑th smallest overall is thus `b[j + k - 1]`.  
   The same reasoning applies symmetrically when `b` is exhausted.

Thus the algorithm always returns the correct **k**‑th smallest element.

### Complexity Analysis

Let `k` be the position requested.

* **Time**  
  Each loop iteration discards one element and decrements `k`.  
  We perform at most `k - 1` iterations, so the time is `O(k)`.  
  In the worst case `k = m + n`, giving `O(m + n)`.

* **Space**  
  Only a few integer variables are used – `O(1)` auxiliary space.
