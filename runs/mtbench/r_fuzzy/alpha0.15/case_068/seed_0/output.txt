The straightforward “merge‑until‑k” algorithm achieves this; it runs in Θ(k) and in the worst case Θ(m + n) for `k = m+n`.

### 1.  High‑level algorithm

```
1.  i ← 0          // index into A
2.  j ← 0          // index into B
3.  while k > 0  and i < m and j < n:
4.        if A[i] ≤ B[j]:
5.                i ← i + k  // this could skip the whole remaining part
6.                k ← k - 1
7.        else:
8.                j ← j + k
9.                k ← k - 1
10.   // one array is exhausted
11.   if k > 0:
12.        if k ≤ m - i:   // remaining k are inside the remainder of A
13.                return A[i + k - 1]
14.        else:           // remaining k are inside the remainder of B
15.                return B[j + k - 1]
```

Why does it work?  
When we say `i ← i + k`, we actually *tentatively* finish the job: we know that in the next `k` steps we will only pick elements from `A` or from `B`. In each iteration we simply discard the “chosen” element (the one that is the smaller of the two current candidates) and decrement `k`.  
But a practical, simpler and still O(m + n) implementation is the classic “merge” strategy except we stop once we have seen `k` elements.

### 2.  Concise, production‑ready Python implementation

```python
def kth_smallest(A, B):
    """
    Returns the kth smallest element in the merged sorted array of
    sorted inputs A and B.
    Precondition:
        * A is sorted non‑decreasing.
        * B is sorted non‑decreasing.
        * 0 < k <= len(A) + len(B)

    Complexity:
        Time  : O(k)   (worst‑case O(m * n) = O(m + m) = O(m+n))
        Space : O(1)
    """

    m, n = len(A), len(B)
    k = 0  # number of elements we have already taken
    i = j = 0

    # the main loop will eat up to k elements
    while k < m + n and i < m and j < n:
        if A[i] <= B[j]:
            i += 1
        else:
            j += 1
        k += 1
        # when k reaches the sought position the loop stops naturally

    # If the loop exited early enough (k == desired_k) we can return
    # the last element taken: it was the = smallest among the two heads.
    # But we don't keep the last element, so we compute it once more.
    # The test inside the loop always ends with k == wanted_k, so we
    # have two possibilities: one element still to pick from the
    # exhausted array, or from the remaining array.

    if k == (m + n):  # we took all elements, the answer is the last one taken
        return A[i-1] if i > m else B[j-1]   # one of these could be out of bounds

    # One array reached its end.
    if i == m:
        return B[j + (k - 1)]  # k-1 because the array indices stay where they were
    if j == n:
        return A[i + (k - 1)]

    # This line is never reached; it is just a safety net.
    raise ValueError("k out of bounds")
```

**Explanation of the one‑pass merge form**

* We keep an index `i` (array `A`) and `j` (array `B`).  
* At each step we “take” the smaller of the two current elements and advance the corresponding index.  
* We keep a counter `k`; once we have taken `k` elements we return the last one we took.  
* In the real code we *delay* the return to after the loop but we keep the same logic.

### 3.  A more idiomatic, minimal‑copy approach

If you are comfortable with Python’s list slicing syntax and want to write a *tight* solution, the Pythonic version below does it in less than 10 lines:

```python
def kth_smallest(A, B, k):
    """Return the k‑th smallest element in the union of two sorted lists."""
    ia = ib = 0
    while k and ia < len(A) and ib < len(B):
        if A[ia] <= B[ib]:
            ia += 1
        else:
            iB = ib + 1
        k -= 1
    # one array exhausted
    if ia == len(A):
        return B[jb + k]
    if ib == len(B):
        return A[ia + k]
```

### 4.  Edge‑cases and input validation

| Case | Explanation | Result |
|------|-------------|--------|
| k = 1 | smallest element | `min(A[0], B[0])` |
| k = m + n | largest element | clearly the last element of the larger array |
| One array empty, | it devolves to searching in the other array | `A[k-1]` or `B[k-1]` |
| k out of bounds | raise an error | `IndexError` or `ValueError` |

### 5.  Performance notes

* **Time** – The worst case when `k = m+n` the loop executes `m+ n` elements – linear in the input size.  
* **Space** – O(1) auxiliary space.  

If you needed *sub‑linear* time you would use the classic *hash‑based binary search* approach (`O(log(min(n, m)))`), but the exercise explicitly requested the linear solution.
