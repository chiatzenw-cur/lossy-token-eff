We have to find the (overall) median of two already sorted arrays  
`A[0 … m‑1]` and `B[0 … n‑1]` where  

* `m` and `n` can be different  
* The algorithm must use only **O(1) additional space** (the two
  input arrays may be read‑only)  
* The running time must be **O(m + n)** – linear in the total number of
  elements.



--------------------------------------------------------------------

#### 1. Direct merge until the median

We only need the element(s) that are in the middle – nothing else.
So we touch in order the two arrays until we have looked at the first

```
mid = (m + n) // 2          # index of the median on 0‑based numbers
```

Elements:

```
  odd total : median is the element at index mid
  even total: median is the average of elements at indices mid–1 and mid
```

During the “merge” we keep two variables:

```
prev = element that was just processed
curr = element that will be processed next
```

When we have processed `mid` elements the current element is the median
(for odd length) and `prev` is the preceding one (required if the
length is even).

--------------------------------------------------------------------
#### 2. Algorithm in detail

```
median_sorted_arrays(a, b):
    i = j = 0                      # pointers into a and b
    prev   = curr = False          # will store last two values

    target = (len(a) + len(b)) // 2  # index of the median element

    for k in range(target + 1):      # we need (target + 1) numbers
        prev = curr

        # pick the next smallest element
        if i < len(a) and (j >= len(b) or a[i] <= b[j]):
            curr = a[i]
            i += 1
        else:
            curr = b[j]
            j += 1

    # now prev = element at index target-1 (if it exists)
    # and curr = element at index target

    if (len(a) + len(b)) % 2 == 1:
        return curr             # odd length
    else:
        return (prev + curr) / 2.0        # even length
```

*No temporary arrays are created – only a few integer variables and two
indices are used, thus **O(1) extra space**.*  
*The loop runs `target+1 = O(m+n)` times, so the time complexity is
`O(m+n)`.*

#### 4. Python implementation

```python
from typing import List, Union

def median_sorted_arrays(a: List[Union[int, float]],
                         b: List[Union[int, float]]) -> float:
    """
    Return the median of the two sorted‑array lists a and b.
    The arrays are assumed to be sorted in ascending order.
    Uses O(1) additional space and O(m+n) time.
    """
    i = j = 0
    prev = curr = 0  # will be overwritten before use

    total_len = len(a) + len(b)
    mid_index = total_len // 2

    # Traverse until we have processed mid_index + 1 elements
    for _ in range(mid_index + 1):
        prev = curr

        # decide which array has the smaller current element
        if i < len(a) and (j >= len(b) or a[i] <= b[j]):
            curr = a[i]
            i += 1
        else:
            curr = b[j]
            j += 1

    # Odd total length => median is the current element
    if total_len % 2 == 1:
        return float(curr)

    # even total length => median is the average of the two middle elements
    return (prev + curr) / 2.0
```

#### 5. Correctness Proof  

We prove that the function returns the correct median.

---

**Lemma 1**  
After executing `k` iterations of the loop,
`prev` equals the k‑th smallest element among the two arrays
(and `curr` is the (k+1)‑th).

*Proof.*  
Initialization: before `k = 0` the loop body has not yet executed,
so `prev` is undefined and `curr` will be set to the smallest element
of the two arrays – the 0‑th smallest.

Inductive step.  
Assume the lemma holds before iteration `k+1`.  
The loop chooses the smallest remaining element of the two lists
thereby appending the next element to the merged order.  
That new element will be the (k+1)‑th smallest overall, and is assigned
to `curr`.  
The preceding value of `curr` (before assignment) is stored in
`prev` and is the k‑th smallest, completing the induction. ∎



**Lemma 2**  
At the end of the loop (`k = mid_index`)  
`prev` equals the element at index `mid_index - 1`,
`curr` equals the element at index `mid_index` (in the merged,
sorted order).

*Proof.*  
Directly from Lemma&nbsp;1 with `k = mid_index`. ∎



**Theorem**  
`median_sorted_arrays` returns the median of the combined sorted
array.

*Proof.*  

*Case 1 – total length odd*  
The median element is the element at index `mid_index`
(0‑based).  
By Lemma&nbsp;2, after the loop `curr` equals exactly this index,
so the function returns it as a floating point number – the correct
median.

*Case 2 – total length even*  
The median element is the arithmetic mean of the two middle elements,
which are at indices `mid_index - 1` and `mid_index`.
Again, by Lemma&nbsp;2, `curr` and `prev` are those two values, thus
the function returns `(prev+curr)/2`, the required median.

Hence the function is correct in all cases. ∎

* **Memory**: Only the indices `i, j` and the two integer variables

from typing import List, Union

def median_sorted_arrays(a: List[Union[int, float]], 
                         b: List[Union[int, float]]) -> float:
    """
    Compute the median of two sorted arrays using O(1) extra space
    and O(n) time, where n is the total length.

    Parameters
    ----------
    a, b : list of numbers, sorted in ascending order

    Returns
    -------
    float : the median
    """
    i = j = 0

    total_len = len(a) + len(b)
    mid_index = total_len // 2

    prev = curr = 0  # will be overwritten before use

    for _ in range(mid_index + 1):
        prev = curr
        if i < len(a) and (j >= len(b) or a[i] <= b[j]):
            curr = a[i]
            i += 1
        else:
            curr = b[j]
            j += 1

    if total_len % 2 == 1:
        return curr  # odd length
    else:
        return (prev + curr) / 2.0
