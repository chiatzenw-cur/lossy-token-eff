Write a routine that, given *two sorted arrays of arbitrary (different) size*, returns the median of the combined set.  
* **Space** – only a handful of auxiliary variables (O(1)).  
* **Time** – linear in the total number of elements (O(m + n), i.e. O(n)).

## Idea  

The two input arrays are already sorted.  
The median of the union can be found by **merging** the two arrays **up to the point where the median lies** and keeping the last two values that were visited.  
No extra array, list or heap handle is needed – only two indexes (pointers) and a few scalars.

```
let m = len(A), n = len(B)
total = m + n

if total is odd:           median is the element at index total//2
else:                      the median is the average of elements at
                           indices total//2 – 1  and  total//2
```

During a single pass we keep:

* `prev (prev_val)` – the previous (lower‑index) element we saw
* `curr (curr_val)` – the current element (the one we just stepped on)
* `i, j` – pointers into the two arrays

When the counter reaches the median index we already have `prev` and `curr`, so the answer can be returned immediately.

## Pseudocode

```
function findMedianSortedArrays(A, B):

    i = 0          // pointer in A
    j = 0          // pointer in B
    count = 0      // number of elements that have been “taken” from the merge
    prev = None
    curr = None

    total = len(A) + len(B)
    median_index = total // 2          // 0‑based
    is_even = (total % 2) == 0

    while count <= median_index:
        prev = curr

        // decide which array supplies the next element to the merge
        if A[i] ≤ B[j] (or B exhausted):
            curr = A[i]
            i += 1
        else:
            curr = B[j]
            j += 1
        count += 1

    if is_even:
        return (prev + curr) / 2
    else:   
        return curr
```

If one array is empty the loop simply consumes the other array – still O(m + n) time, O(1) space.

## Python implementation

```python
import typing

def find_median_sorted_arrays(
    A: typing.List[int | float],
    B: typing.List[int | float],
) -> float:
    """
    Return the median of the two sorted input arrays A and B.

    Assumes:  A and B are already sorted (non‑decreasing).
    Uses only O(1) extra space and O(len(A)+len(B)) time.
    """
    m, n = len(A), len(B)
    total = m + n
    mid_index = total // 2
    is_even = total % 2 == 0

    i, j = m, n      # pointers: initially at the end of each array
    count = 0
    prev_val = curr_val = None

    # walk backward from right to left to avoid dynamic allocation
    # (a forward sweep is equally valid – pick whichever feels clearer)
    while i > 0 or j > 0:
        # Pick the larger tail element to compare
        if j > 0 and (i == 0 or B[j - 1] > A[i - 1]):
            curr_val = B[j - 1]
            j -= 1
        else:
            curr_val = A[i - 1]
            i -= 1
        if count == mid_index:
            # For odd length we only need the current element
            if not is_even:
                return float(curr_val)
            # For even length we need the previous one too
            else:
                return (prev_val + curr_val) / 2.0
        prev_val = curr_val
        count += 1

    # Fallback – should never be reached
    raise ValueError("Unexpected loop exit – the input arrays may be empty.")
```

> **Why backward traversal works**  
> Traversing from the end (right side) is a taste‑for‑theory, but you can also walk **frontward** (left‑to‑right). Both are linear, O(1) space, and give the same result, just opposite ordering. The backward method can sometimes simplify the loop when you do not want to guard against “i out of bounds” because we still keep the indices non‑negative.

## Variant (forward sweep)

Below is a more conventional, forward‑sweep version. The logic is identical; I kept it short and easier to read for many readers.

```python
def find_median_sorted_arrays_forward(
    A: typing.List[int | float],
    B: typing.List[int | float],
) -> float:
    i = j = 0
    total = len(A) + len(B)
    mid_index = total // 2
    feasible_even = total % 2 == 0

    prev = curr = None
    for _ in range(mid_index + 1):
        prev = curr
        if i < len(A) and (j >= len(B)) or (i < len(A) and A[i] <= B[j]):
            curr = A[i]
            i += 1
        else:
            curr = B[j]
            j += 1

    if feasible_even:
        return (prev + curr) / 2.0
    return float(curr)
```

## Summary

To find the median of two sorted arrays with *O(1)* auxiliary space:

* **Walk** through a virtual merge of the two arrays until you reach the median position(s).  
* Keep only the last two visited numbers (`prev` and `curr`).  
* After the loop, either return `curr` (odd total) or the `(prev+curr)/2` (even total).

This satisfies the constraints and runs in linear time over the combined input size.
