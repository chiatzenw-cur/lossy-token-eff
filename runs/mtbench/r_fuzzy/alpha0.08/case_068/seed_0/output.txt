    return the k‑th smallest element in their (multiset) union.
    The function works in O(k) time and O(1) additional space.

    Parameters

    b : list[int]

### Why it’s linear time  

The algorithm only moves the two pointers forward; each move consumes **one element** from the union.  
We stop as soon as we have consumed `k` elements, so the *worst‑case* work is `k` comparisons –  
`O(k)` time.  
If we query for the very last element (`k = m+n`), the algorithm will walk all `m+n` elements – still linear in the length of the input.

The extra space is constant (`O(1) extra`), apart from the input lists.

### When you really *don't* need duplicates  

If you truly want the mathematical *union* (duplicates removed, treating each list as a set), insert a simple check:

```python
prev = None
while i < m and j < n:
    val = a[i] if b[j] > a[i] else b[j]
    # skip duplicates
    if val != prev:
        count += 1
        if count == k:
            return val
        prev = val
    # advance the pointer that supplied `val`
    i += 1 if val == a[i] else 0
    j += 1 if val != a[i] else 0
```

But for the common interview question – when duplicates *do* count – the straightforward merge, as above, is the simplest linear‑time solution.
