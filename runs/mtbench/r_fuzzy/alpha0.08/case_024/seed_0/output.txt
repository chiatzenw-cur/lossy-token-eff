The task is to list all values that appear in **both** arrays, without allocating a separate data structure such as a set, hash‑table, or an auxiliary list.

The simplest way to achieve this with *O(1)* extra memory is:

1. **Sort** **both** input arrays (in‑place sorting – e.g. quicksort/radix sort).  
2. Scan the two sorted arrays with two indices (`i` for the first array, `b` for the second).  
3. When the two current values are equal, output the value and advance both indices.  
4. If the value in array 1 is smaller, advance `i`; otherwise advance `b`.

Sorting is the only place that uses temporary variables, but the algorithm itself does **not** keep any additional data structures for the result.  The total auxiliary memory is `O(1)` (apart from the recursion stack of the sorting routine or the loop variables).

The time complexity is dominated by the sorting step, i.e. `O(n log n + m log m)` where `n` and `m` are the sizes of the two arrays.  The merging pass is linear, `O(n+m)`.

Below is a concrete implementation in **C++**.  
(Any language can be implemented analogously – the idea is the same.)

---

## C++ Implementation

```cpp
#include <iostream>
#include <vector>
#include <algorithm>   // std::sort

// Print the common elements of two arrays.
// Arrays are modified (sorted) in place, but otherwise no extra data structures are used.
void commonElements(std::vector<int>& a, std::vector<int>& b)
{
    // 1. Sort both arrays.
    sort(a.begin(), a.end());
    sort(b.begin(), b.end());
    
    // 2. Two‑pointer scan.
    size_t i = 0, j = 0;
    std::cout << "Common elements: ";
    bool first = true;          // for pretty printing

    while (i < a.size() && j < b.size())
    {
        const int va = a[i];
        const int vb = b[j];

        if (va == vb)
        {
            if (first) { first = false; } else { print space; }
            std::cout << va;

            // Skip duplicates inside each array to avoid printing the same value twice.
            ++i;
            ++j;
            while (i < a.size() && a[i] == va) ++i;  // no extra memory
            while (j < b.size() && b[j] == vb) ++j;
        }
        else if (va < vb)
        {
            ++i;          // advance the smaller value
        }
        else
        {
            ++j;              // advance the smaller value
        }
    }
    std::cout << '\n';
}

int main()
{
    std::vector<int> arr1A = {1, 5, 10, 20, 40, 80};
    std::vector<int> arr1B = {6, 7, 20, 80, 100};

    std::vector<int> arr2A = {3, 5, 7, 12, 20, 30, 40};
    std::vector<int> arr2B = {1, 3, 4, 6, 12, 20, 40, 50};

    std::cout << "Example 1:\n";
    commonElements(arr1A, arr1B);          // outputs 20 80

    std::cout << "Example 2:\n";
    commonElements(arr2A, arr2B);          // outputs 3 12 20 40

    return 0;
}
```

### Explanation of the code

1. **Sorting** – `std::sort` uses `O(1)` additional memory (beyond the stack used by the function).  It arranges the elements in ascending order.

2. **Two‑pointer traversal** –  
   * `i` indexes the current element of `a`, `j` indexes the current element of `b`.  
   * The loop terminates when one of the indices reaches the end of its array.  
   * When `a[i] == b[j]`, the value is part of the intersection.  
   * After printing, the code skips over any duplicate occurrences of this value in both arrays, preventing duplicate outputs.

3. **No extra data structures** –  
   * Only a handful of integer pointers/indices are used.  
   * No `std::set`, `std::priority_queue`, or temporary vector/list is created.

4. **Output** – The code prints the common elements separated by spaces.

---

## Why this satisfies the requirement

The algorithm uses `O(1)` extra memory and **no additional data structures**.  
It only requires the arrays themselves (which are modified in‑place).  

If in-place sorting is disallowed (e.g. the original order must be preserved), you can still use the two‑pointer method by first copying duplicates into a single temporary array *only for the purpose of issuing results*, but that would technically violate “no extra data structures.”  In the strictest reading, sorting the original arrays in place is expected.

---

### Alternative – No Sorting Allowed

If you really cannot change the input arrays, you must resort to a **quadratic scan**:

```cpp
for (size_t i = 0; i < a.size(); ++i) {
    for (size_t j = 0; j < b.size(); ++j) {
        if (a[i] == b[j]) {
            // print a[i], but avoid duplicates by earlier checks
        }
    }
}
```

This is still `O(n*m)` time and `O(1)` space, but it will be much slower for large arrays.  The sort‑+‑two‑pointer approach is the most efficient way while still meeting the “no extra data structures” rule.
