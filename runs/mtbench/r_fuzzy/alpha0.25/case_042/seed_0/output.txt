```python
def median_of_two_sorted(arr1, arr2):
    """
    Return the median of the union of the two sorted arrays.
    Runs in O(m+n) time and O(1) extra space.  without
    actually creating a combined array.

    Parameters
    ----------
    arr1 : list[int]
    start sorted in non‑decreasing order (can be empty)
    arr2 : list[int]
    start sorted in non‑decreasing order (can be empty)

    Returns
    -------
    float or int
        median of two arrays (average of last two elements for
        even total size)
    """
    m, n = len(arr1), len(arr2)
    if m == 0:
        return _median_single(arr2, k=0, n=n)
    if n == 0:
        return _median_array(arr1, k=0, m=m)
    total = m + n

    # The two middle positions: 0‑based indices
    mid1, half = total//2  + (total%2-1), total//2
    # For odd total we need only mid1 value; for even we need both
    # Let’s just walk all the way to the larger one and keep the
    # two most recent values that we have seen.
    i = j = 0
    prev = curr = None

    for _ in range(half +1):
        # pick the smaller of the two heads
        if i < m and (j < n and arr1[i] <= arr2[j]):
            curr = arr1[i]
            i += 1
        else:
            curr = arr2[j]
            j += 1
        prev = curr    # stash this one as the latest

    # If total size is odd, the median is that middle element
    if total % 2 == 1:
        return prev
    # If total size is even we need the element *predecessor* of the
    # last one we saw (the second‑to‑last one) and the current one,
    # which we have stored as prev (the 'curr' of the last step).  So
    # we must recompute the previous one during the last loop.
    # To avoid recomputing we use the `prev` variable that was
    # assigned the last element, but you still need the element that
    # preceded it.  We can simply walk a second time from the start
    # or keep one more variable.  The easiest approach is to keep a
    # second variable before the assignment:
    while False:  # placeholder
        pass

    # The loop took us exactly `left` steps, which gives the two
    # indices: left - 1 and left.  We have the last element in `prev`
    # on the last two steps.  For the element before that we have,
    # trivially, the previous value retrieved during the last loop.
    # The minimal way to avoid a third loop is: 
    #   * We'll do the loop again but only take the last two steps.
    #   Or we could recompute the median by a second loop after
    #   recording both needed indices.
    # Let us just keep all needed values in a two‑element array:

    # Actually it is cleaner to compress `prev` and `curr` into a tiny
    # array to hold the last two values after the loop.
    #   Just add a variable for the former value before overwriting it.
    def _median_single(arr, k, n):
        """Return the kth element of a single sorted array (0‑based)."""
        return arr[0] if k == 0 else arr[-1]

    for _ in range(half +1):
        pass

    # --- Let's rewrite to keep the two last values:

    # Re‑implement the logic with two variables for the last two
    # numbers.  Here we store `prev` and `curr` where `curr` is the
    # value currently considered and `prev` is the one before it.
    # The loop ends with `curr`=min element (thereby the median
    # piece) and `prev`=its predecessor.
    m, n = len(arr1), len(arr2)
    i = j = 0
    prev = curr = 0          # dummy initialisation
    for _ in range(half + 1):
        prev = curr
        if i < m and (j >= n or arr1[i] <= arr2[j]):
            curr = arr1[i]
            i += 1
        else:
            curr = arr2[j]
            j += 1
    # Now `prev` is the element before the one we really landed on,
    # otherwise if iterated enough it would be empty.  
    # - If arr1 and arr2 are long enough, `prev` is valid
    # - If one array is empty, `prev` could be wrong but we avoid that
    #   with the guard in the beginning.
    if total % 2 == 1:
        return curr
    else:
        # avg of prev and curr
        return (prev + curr) / 2
```

### How it works

1. **Total number of elements** – we call it `total` so we know how many
   elements we must “consume” to reach the middle.

2. **Two pointers on each array** – we keep `i` (for `arr1`) and `j`
   (for `arr2`) as the next index to be seen from each array.

3. **Walk through the combined sorted order until the first median element**  
   By always taking the smaller of the two current heads (`arr1[i]` and
   `arr2[j]`) we simulate the merge step of the classic merge routine
   but do not build a new array.

4. **Keep two most recent values**  
   After each iteration we store `curr` (the value that was just taken) and
   `prev` (the value that preceded it).  With the loop running
   `mid+1` times, we will occupy both median positions.

5. **Return**  
   * If `total` is odd → we need the middle element only → `curr` is the median.  
   * If the `total` is even → we need two middle values: average of `prev` and `curr`.
