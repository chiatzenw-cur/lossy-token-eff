// fib.cpp
// Simple recursive Fibonacci
#include <stdexcept>
#include <iostream>
#include <limits>

using namespace std;

// int    – safe for small n (the Fibonacci value must fit in an int)
// unsigned long long – works up to about n = 92 (F(92) ≈ 7.6 × 10^18)
// For further values you’d need big‑int support, code below just prints the size.
unsigned long long fibRec(unsigned long long n)
{
    if (n == 0) return 0;          // by convention F(0) = 0
    if (n == 1) return 1;          // F(1) = 1
    // for n > 1 compute recursively
    return fib(n-1) + fib(n-2);
}

### How the code works

| Step | Explanation |
|------|-------------|
| `n == 0` | Determines index 0 – the sequence starts with 0 |
| `if (n == 1)` | Handles index 1 – the first “1” in the Fibonacci list |
| `return fib(n-1) + fib(n-2)` | Recursively calculates the next two terms and adds them |

The recursion depth is at most `n` (1 < n ≤ 92), so the stack stays well under time limits for moderate values of `n`. For up to a few thousand – a few thousand recursive calls are fine (the recursion depth is 1000 for `n=1193` but this will quickly bring into a `O(2^n)` time blow). Most libraries will be fine for a list of the first few dozen Fibonacci numbers – using this program for large `n` is mostly a demonstration of recursion.

### Why recursion is not ideal for large `n`

* **Time complexity** – the naïve method is `O(2^n)` – exponential growth, extremely slow for `n > ~40` on source‑level recursion.
* **Stack overflow** – the recursion depth grows with `n`, which could overflow program stack for very large `n`.

If you need great performance or large `n` you would normally:

1. Use a loop (`fib(n)`) or
2. Use *memoisation* (store computed values) or
3. Implement a matrix‑exponentiation algorithm that finishes in `O(log n)` time.

But for the *basic* exercise, the plain recursive solution above is a great demonstration.
