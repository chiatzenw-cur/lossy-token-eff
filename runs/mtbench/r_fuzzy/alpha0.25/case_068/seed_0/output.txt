For two already‑sorted lists  

```
A[0 … m‑1]  – length m
B[0 … n‑1]  – length n
```

we can merge them “on‑the‑fly” until we reach the *k*‑th smallest element.  
The usual merge routine from merge‑sort does exactly this:

* keep two indices `i` and `j` (`i` into `A`, `j` into `B`);
* in each step pick the two current elements and advance the one that is
  smaller (or the only that exists when the other list is exhausted);
* keep a counter `cnt` that counts how many elements were already taken.
* The element that makes *cnt* equal to *k* is the answer (1‑based index).

Because merges only touch every element at most once, the total work is  
`O(m + n)` – linear in the combined sizes.

The space usage is `O(1)` (we only keep the two indices and the counter).

### Formal Algorithm (pseudocode)

```
function kth_smallest(A, B, k):
    // Assume 1 ≤ k ≤ m + n
    i ← 0
    j ← 0
    cnt ← 0

    while i < len(A) and j < len(B):
        if A[i] < B[j]:
            elementA[i] ← A[i]
            i ← i + 1
        else:
            elementA[i] ← B[j]
            j ← j + 1
        cnt ← cnt + 1
        if cnt == k:
            return elementA[i−1]

    // One list exhausted – the right list holds the rest
    while i < len(A) and cnt < k:
        i ← i + 1
        cnt ← cnt + 1
        if cnt == k:
            return A[i-1]

    while i < len(B) and cnt < k:
        j ← j + 1
        cnt ← cnt + 1
        if cnt == k:
            return B[j-1]

    // If k is out of bounds (not expected per contract)
    raise ValueError(f"k={k} is not in {len(A)+len(B)}")
```

**Complexities**

* **Time**: `O(m + n)` – at most `m+n` comparisons.
* **Space**: `O(1)` – only a few integer indices and counters.

### Python Implementation

```python
def kth_smallest_two_sorted_lists(A, B, k):
    """
    Return the kth smallest element (1‑based) of the union of
    two sorted lists A and B.
    Assumes 1 <= k <= len(A)+len(B)

    Parameters
    ----------
    A : list[int | float]
        First sorted list, ascending order.
    B : list[int | float]
        Second sorted list, ascending order.
    k : int
        1‑based index of the desired element.

    Returns
    -------
    int | float
        The kth smallest element.

    Raises
    ------
    ValueError
        If k is out of bounds.
    """
    m, n = len(A), len(B)
    k = int(k)                # safety – allow array‑like inputs

    if k < 1 or k > m + n:
        raise ValueError(f"k={k} is out of bounds for lists of length {m} and {n}")

    i, j = 0, 0          # indices into A and B
    count = 0            # number of elements already taken

    # Merge the two lists until we hit the kth element
    while i < m and j < n:
        if A[i] <= B[j]:
            count += 1
            if count < k:
                i += 1                       # skip A[i]
            else:
                return A[i]
        else:
            count += 1
            index_b = j
            if count < k:
                j += 1                       # skip B[j]
            else:
                return B[index_b]

    # If we ran out of elements of A
    while i < m:
        count += 1
        if count < k:
            i += 1
        else:
            return A[i]

    # If we ran out of elements of B
    while j < n:
        count += 1
        if count < k:
            j += 1
        else:
            return B[j]

    # Should never reach here because K > 0 <= m + n
    # (but guard against overflow cases)
    raise RuntimeError(f"Unexpected state: k={k}, t={count}")

# Demo
if __name__ == "__main__":
    A = [1, 3, 5, 7, 9]   # sorted
    B = [2, 4, 6, 8, 10]  # sorted
    for k in [1, 3, 4, 6, 7, 8, 10, 12]:
        print("kth", k, "=", kth_smallest_two_sorted_lists(A, B, k))
```

### Complexity Discussion

*For each iteration the algorithm looks at either `A[i]` or `B[j]`.  
Since each element is either seen once (we skip the `<=` comparison) or is
the final returned element, it touches at most `m+n` elements.*

* The loop therefore runs ≤ `m + n` times → `O(m + n)` time.
* Only a few integer variables (indices, counters, `k`) are kept → `O(1)` space.

--------------------------------------------------------------------

#### Variations

* If you wish to **count duplicates** separately, keep the same algorithm –
  the identical elements are counted one by one, as the merge routine does.
* If you absolutely need **log‑time** you can use the “find smallest in
  two sorted arrays” algorithm segmenting both lists at half‑points,
  but the problem statement explicitly requested a linear time solution.

--------------------------------------------------------------------

### Bottom line

The merge‑style walk through the two sorted lists is a textbook
`O(m+n)` linear‑time solution for the k‑th smallest element in the union.  
Because the lists are already sorted, no additional sorting is
required, and the algorithm is trivial to read and implement.
