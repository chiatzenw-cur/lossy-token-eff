In the context of a binary tree, the “highest” common ancestor is the **lowest** node that is an ancestor of both target nodes – i.e. the classic Lowest‑Common‑Ancestor (LCA).  
If you literally meant the ancestor that is farthest up the tree (the root), the function simply returns the root because the root is the only node that is common to all descendants.

The code below assumes that you’re given pointers (or references) to the two target nodes (`p` and `q`).  
If you only have the values, you’ll first need to locate the actual nodes (or modify the routine to search by value).

# Definition of a binary tree node

        self.val   = val
        self.left  = left
        self.right = right

## 1. Recursive LCA (most common, easy to understand)

```python
def find_highest_common_ancestor(root: TreeNode,
                                 p: TreeNode, q: TreeNode) -> TreeNode:
    """
    Return the lowest (i.e., highest in the tree) common ancestor of nodes p and q.
    Assumes both p and q exist in the tree and all tree nodes have unique values.
    """
    # base case: if current node is None or one of the targets
    if root is None or root is p or root is q:
        return root

    # recurse on left and right sub‑trees
    left  = find_highest_common_ancestor(root.left,  p, q)
    right = find_highest_common_ancestor(root.right, p, q)

    # If both sides return non‑None, current node is the common ancestor
    if left and right:
        return root

    # Else return the non‑None side (or None if both are None)
    return left if left else right
```

### How it works

* Recursively search both sub‑trees.
* If the current node equals one of the targets, we already have an ancestor.
* When a node’s left AND right sub‑trees return a non‑None result, that node must lie **above** `p` *and* `q`, so it is the HCA.

## 2. Alternative: Hash‑set + parent pointers

If each node has a `parent` reference (or you construct one), you can do an O(N) preprocessing step and then answer queries in O(h) time:

```python
def build_parent_map(root: TreeNode):
    parent = {root: None}
    stack  = [root]
    while stack:
        node = stack.pop()
        if node.left:
            parent[node.left] = node
            stack.append(node.left)
        if node.right:
            parent[node.right] = node
            stack.append(node.right)
    return parent

def highest_common_ancestor_with_parent(root: TreeNode,
                                       p: TreeNode, q: TreeNode) -> TreeNode:
    # Build parent dictionary once
    parent = build_parent_map(root)

    # Track all ancestors of p
    ancestors_of_p = set()
    cur = p
    while cur:
        ancestors_of_p.add(cur)
        cur = parent[cur]

    # Walk up from q until we find a common ancestor
    cur = q
    while cur:
        if cur in ancestors_of_p:
            return cur
        cur = parent[cur]
    return None   # should never reach if p, q are in the tree
```

| Approach | Time (finder) | Space | Notes |
|----------|---------------|-------|-------|
| Recursive LCA | `O(N)` – tree is traversed once | `O(h)` – recursion stack (h = height) | No extra data structures needed |
| Parent‑dictionary | `O(N)` preprocessing + `O(h)` query | `O(N)` | Good for many queries |

## 3. In‑order  (iterative) – if you only have node values

If you don’t have direct node references but only the values of `p` and `q`, modify the recursive routine to compare node values, and optionally return `None` if the target isn’t found:

```python
def find_hca_by_value(root: TreeNode, val_p: int, val_q: int) -> TreeNode:
    def helper(node):
        if node is None:
            return None, False, False
        left_node, left_has_p, left_has_q = helper(node.left)
        right_node, right_has_p, right_has_q = helper(node.right)

        has_p = left_has_p or right_has_p or (node.val == val_p)
        has_q = left_has_q or right_has_q or (node.val == val_q)

        # If this node is the LCA:
        if (node.val == val_p or node.val == val_q) and (left_has_p or left_has_q or right_has_p or right_has_q):
            return node, has_p, has_q
        if left_has_p and left_has_q:
            return node, has_p, has_q
        if right_has_p and right_has_q:
            return node, has_p, has_q

        # Pass up whichever side contains a target
        candidate = left_node if left_node else right_node
        return candidate, has_p, has_q

    result, _, _ = helper(root)
    return result
```

## 4. Edge cases & sanity checks

1. **Both nodes are the same:**  The node itself is the HCA (common ancestor of itself).
2. **One node is ancestor of the other:**  The ancestor node is the HCA.
3. **Nodes not present in the tree:**  You should decide whether to return `None` or raise an exception.  The recursive approach will return `None` if one or both targets aren't found because the base‑case return passes `None` back up the recursion.
