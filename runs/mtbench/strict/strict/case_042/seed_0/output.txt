* **O(1) auxiliary space** – we only use a handful of scalar variables;  
* **O(m + n) = O(n)** time – we walk through each array once, no extra copying.

The algorithm is essentially a *partial merge* of the two arrays. We only walk until we reach the median position, so we never build a full merged array.

---

## 1.  Core Idea

If the two arrays are merged into one sorted array `C`:

```
C[0 … (m+n-1)]
```

the median indices are

```
pos1 = (m+n-1) // 2                // floor median for odd total
pos2 = (m+n)   // 2                // ceil median for odd total
```

If the total number is odd, `pos1 == pos2`.  
If it is even, the median is the **average** of `C[pos1]` and `C[pos2]`.

During a single pass we keep two pointer indices `i` and `j`, pointing at the current item in each array. We march the smaller of the two items forward, counting how many items we've “output” so far. As soon as the counter reaches `pos1` or `pos2` we record the value. When the counter exceeds `pos2` we can stop; we have all the numbers we need.

Because we only keep a few integer variables (`i, j, count`, the two median candidates), the extra space usage is constant.

### 3.1  C++ (C++17)

```cpp
#include <vector>
#include <stdexcept>

// ---------------------------------------------------------------------
// findMedianSortedArrays
//   Given two sorted arrays (not necessarily of the same size), return
//   the median of all elements.  Expected to work with ints, but you
//   can template it if you wish.
//
//   Complexity : O(m+n) time, O(1) extra space
// ---------------------------------------------------------------------
double findMedianSortedArrays(const std::vector<int>& A,
                              const std::vector<int>& B)
{
    std::size_t m = A.size(), n = B.size();
    // Handles the degenerate case of both arrays being empty
    if (m == 0 && n == 0)
        throw std::invalid_argument("Both input arrays are empty");

    std::size_t total = m + n;
    std::size_t pos1 = (total - 1) / 2;   // lower middle index
    std::size_t pos2  = total / 2;        // upper middle index

    std::size_t i = 0, j = 0;              // indices into A and B
    std::size_t count = 0;                 // how many elements have been "taken"
    int  val1 = 0, val2 = 0;               // values of the needed elems

    // Merge until we have passed pos2
    while (count <= pos2) {
        int next;

        // Decide which array to take from
        if (i < m && (j >= n || A[i] <= B[j])) {
            next = A[i];
            ++i;
        } else {
            next = B[j];
            ++j;
        }

        if (count == pos1) val1 = next;  // first median element
        if (count == pos2) {             // second median element
            val2 = next;
            break;                       // we are done
        }

        ++count;
    }

    // If total is odd, pos1 == pos2, so val1 == val2
    return (val1 + val2) / 2.0;            // safe for both odd & even totals
}
```

**Usage example**

```cpp
#include <iostream>
int main() {
    std::vector<int> a{1, 3, 5};
    std::vector<int> b{2, 4, 6, 8};
    std::cout << findMedianSortedArrays(a, b) << '\n';   // prints 4
}
```

### 3.2  Python

```python
def median_of_two_sorted(a, b):
    """Return the median of two sorted integer lists a and b.
    Works in O(len(a)+len(b)) time and O(1) extra space."""
    m, n = len(a), len(b)
    if m == n == 0:
        raise ValueError("Both inputs are empty")

    total = m + n
    pos1 = (total - 1) // 2
    pos2 = total // 2

    i = j = count = 0
    val1 = val2 = 0

    while count <= pos2:
        if i < m and (j >= n or a[i] <= b[j]):
            nxt = a[i]
            i += 1
        else:
            nxt = b[j]
            j += 1

        if count == pos1:
            val1 = nxt
        if count == pos2:
            val2 = nxt
            break

        count += 1

    return (val1 + val2) / 2.0
```

**Example**

```python
>>> a = [1, 3, 5]
>>> b = [2, 4, 6, 8]
>>> median_of_two_sorted(a, b)
4.0
```

## 4.  Why This Works

* **Never builds a full merged array** – we only keep a *running pointer* into the combined order.  
* **Stops as soon as median indices are reached** – for an odd total we stop after one more element (`pos1 == pos2`); for an even total we stop after the second median value.  
* **No auxiliary storage** – the only variables we use are indices, counters, and two integers for the median candidates.

The only subtle point is handling the two median indices (`pos1` / `pos2`).  Because the merge proceeds in sorted order, when `count == pos1` the value we just pulled is exactly `C[pos1]`.  The same holds for `pos2`.  When `total` is odd, `pos1 == pos2`, so we record the same value twice, and the average of identical numbers is the value itself.

### 5.  Further Optimizations (if needed)

The above runs in `O(m+n)` time, which meets the requirement of **O(n)**.  
If you need *logarithmic* time (better than `O(n)`) you can use the binary‑search‑based partition technique (median of medians), but that requires `O(log(min(m,n)))` time and still only `O(1)` space.  Since the question explicitly asks for `O(n)`, the simple merge‑walk is the cleanest solution.
