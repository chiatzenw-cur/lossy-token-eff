The idea is the same as the “merge” step of merge‑sort.  
While we haven’t yet consumed *k* elements, we keep two pointers—`i` into the first array `A` and `j` into the second array `B`.  
At each step we take the smaller of the two current elements (or the only one that still exists if one array is exhausted), advance that pointer and decrement *k*.  
When *k* reaches zero the last element we *peeked at* is the *k*‑th smallest in the union.

Because in every iteration exactly one pointer is advanced, the loop runs at most *k* times.  
If *k* may be as large as *m + n*, the algorithm is still linear in the size of the two input lists.

---

### Python implementation

```python
def kth_smallest(A, B, k):
    """
    Return the kth smallest element (1‑based) in the union of
    two sorted lists A and B.  Array indices are 0‑based.
    
    Parameters
    ----------
    A : list[int]
        First sorted list (size m)
    B : list[int]
        Second sorted list (size n)
    k : int
        Desired order statistic (1 ≤ k ≤ m + n)

    Returns
    -------
    int or float
        The k‑th smallest element, or raises ValueError if k is out of bounds.
    """
    m, n = len(A), len(B)
    if k < 1 or k > m + n:
        raise ValueError("k is out of bounds")

    i = j = 0          # current indices for A and B
    while k:
        # One array has been exhausted – the answer lies in the other
        if i == m:
            return B[j + k - 1]
        if j == n:
            return A[i + k - 1]

        # Decide which pointer to advance
        if A[i] <= B[j]:
            i += 1           # A[i] is the current smallest candidate
        else:
            j += 1           # B[j] is the current smallest candidate
        k -= 1               # one element is "used up"

    # k has become 0 – the last element popped is the answer
    # (actually we never reach here because we would have returned
    # inside the loop when one array is depleted)
```

### Usage example

```python
A = [1, 4, 5, 8, 12]
B = [2, 3, 6, 7, 10, 14]

print(kth_smallest(A, B, 1))   # 1
print(kth_smallest(A, B, 3))   # 3
print(kth_smallest(A, B, 7))   # 7
print(kth_smallest(A, B, 10))  # 12
```

---

### Why the algorithm is correct

* Both lists are sorted, so at any time the smallest unconsumed element in
  the union must be the smaller of the current elements in `A` and `B`.
* By advancing the pointer to the list that owns the current smallest
  element we effectively “remove” that element from consideration.
* Every iteration removes exactly one element from the front of the
  merged sequence; after `k` iterations the next element that would be
  removed is the *k*‑th smallest overall.

---

### Complexity

* **Time** – At most one pointer is advanced per loop iteration,
  and we advance a pointer `k` times.  
  Worst‑case: `k = m + n` → `O(m + n)` time.

* **Space** – `O(1)` extra memory (only the two indices and a few scalars).

### Optional: O(log (m+n)) solution

If you need *sub‑linear* time, a divide‑and‑conquer approach can find the
k‑th smallest element in `O(log(m+n))` time.  
It skips roughly half of the remaining elements in each step by comparing
the k/2‑th element of each array and discarding a chunk that cannot
contain the answer.  
However, the question explicitly asked for a linear‑time solution, so
the merge‑like algorithm above satisfies that requirement.
