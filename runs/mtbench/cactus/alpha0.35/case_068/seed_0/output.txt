#### Problem recap  
Input: two *sorted* lists  

```
A = [a0, a1, …, a(m‑1)]   // length m
B = [b0, b1, …, b(n‑1)]   // length n
```

Return the `k`‑th smallest element in the *union* of the two lists (1‑based indexing).  
If `k = m+n` the answer is the largest element of the two lists.  
The algorithm must be **linear** so that the worst‑case time is `O(m + n)`.



---

### 1.  Why linear?  
In the usual two‑pointer merge approach, the two pointers always move toward the end
the sequences that are already “exhausted”.  
When we have consumed `k` elements we know what the k‑th from the start is.  
No extra tricks are required – the algorithm is *essentially* “merge A with B until you
 hit the k‑th element”.

Because every element is inspected at most once (either the `i`‑pointer or the `j`‑pointer
multiplies it), the total number of operations is bounded by `m+n`.  
Thus, the algorithm is under **amortized** time and uses *O(1)* extra space.



---

### 2.  Algorithm (pseudo‑code)

```
kth_smallest(A, B, k):
    m = len(A)
    n = len(B)
    if k < 1 or k > m + n:
        raise ValueError("k is out of bounds")

    i = 0              // current index in A
    j = 0              // current index in B
    indices_taken = 0

    while i < m and j < n:
        // Choose the smaller of the two current elements
        if A[i] <= B[j]:
            indices_taken += 1
            if indices_taken == k:
                return A[i]
            i += 1
        else:
            indices_taken += 1
            if indices_taken == k:
                return B[j]
            j += 1

    // One array ran out – just copy from the other
    while i < m and indices_taken < k:
        indices_taken += 1
        if indices_taken == k:
            return A[i]
        i += 1

    while j < n and indices_taken < k:
        indices_taken += 1
        if indices_taken == k:
            return B[j]
        j += 1

    // we should never reach here earlier
    raise RuntimeError("Logic error")
```

### 3.  Correctness proof (sketch)

1. **Invariant to the first `while` loop**  
   *At the start of each loop iteration, at most `k-1` elements have been “taken” and
   all elements taken are the `k-1` smallest of the merged prefix.*

2. **Move to next smallest element**  
   The smaller of `A[i]` and `B[j]` gives the next element in the merged order.
   Taking it also guarantees that the chosen element is still the smallest among the
   unprocessed values.

3. **Termination**  
   When `indices_taken == k` the element just added is the `k`‑th smallest; returning it
   is therefore correct.

4. **Auxiliary cases**  
   After one array is exhausted, the remaining elements are already sorted by the
   non‑decreasing article.  
   Taking the next element of the remaining array continues the same construction
   until `k` hits.

Thus the algorithm always collects the requested element in the correct way.

The overall running time is `O(m + n)` – one linear scan.

### 5.  Reference implementation

```python
def kth_smallest(A, B, k):
    """
    Return the k-th smallest element in the union of the sorted lists A and B.

    Parameters
    ----------
    A, B : list of comparable items
        The two input lists must be sorted in non‑decreasing order.
    k : int
        1‑based index of the desired element. Must be present (1 <= k <= len(A)+len(B)).

    Returns
    -------
    value : the k-th smallest element

    Raises
    ------
    ValueError
        If k is out of bounds.
    """
    m, n = len(A), len(B)
    if k < 1 or k > m + n:
        raise ValueError("k is out of bounds")

    i = j = 0  # current pointers
    counts = 0

    while i < m and j < n:
        if A[i] <= B[j]:
            counts += 1
            if counts == k:
                return A[i]
            i += 1
        else:
            counts += 1
            if counts == k:
                return B[j]
            j += 1

    # one array exhausted, keep consuming from the other
    while i < m and counts < k:
        counts += 1
        if counts == k:
            return A[i]
        i += 1

    while j < n and counts < k:
        counts += 1
        if counts == k:
            return B[j]
        j += 1

    # The heap should never reach here before k was found
    raise RuntimeError("Kth value not found; input valid but algorithm logic fails.")
```

### 7.  Edge‑cases and notes

| Edge case | What to do |
|-----------|------------|
| `k == 1` | print the minimum of the two lists |
| `k == len(A)+len(B)` | print the maximum of the two lists |
| Duplicate values | Works fine – the algorithm keeps picking which one is the smaller at each store; equal items treat counts correctly |
| Duplicate list boundaries | The algorithm keeps the “strictly sequential” order – duplicates are counted among the k‑th smallest |

If `m` and `n` are very large and the lists are large but only the small `k` is consulted, the algorithm is still `O(k)` because we stop here immediately.  
More sophisticated algorithm variants (Hunts & Lang's algorithm for computing the k‑th element in *O(log k)* time) achieve sub‑linear time, but in the problem statement it is *linear* to meet the stringent bounds.
