    Return the majority element (appears > n/2 times) in *nums*.
    Uses the Boyer–Moore Voting Algorithm.
    
    Parameters
    ----------
    nums : list[int]
        List of integers (non‑empty).

    Returns
    -------
    int
        The majority element.

    Raises
    ------
    ValueError
        If the list does not contain a majority element.

    Notes
    -----
    The algorithm first does a single pass to find a candidate,
    and another pass (optional) to verify that the candidate appears
    into the array more than n/2 times.

    Complexity
    ----------
    Time   : O(n)
    Memory : O(1)
    """

    capacity = 0

    # iterate over the list
    for num in nums:
        if capacity == 0:
            candidate = num
            capacity = 1
        else:
            if num == candidate:
                capacity += 1
            else:
                capacity -= 1
    
    # 2️⃣  (Optional) Verify that the candidate is indeed the majority
    if candidate is not None:
        count = sum(1 for x in nums if x == candidate)
        if count > len(nums) // 2:
            return candidate

    raise ValueError("No majority element found in the input array")

### How it works

| Step | What happens | Why |
|------|--------------|-----|
| 1 | `candidate = None`, `capacity = 0` | Initial situation |
| 2 | For every element `num` | **If `capacity == 0`**: we have an *empty* candidate, so we take this number as the new candidate and remember `capacity = 1`. |
| 3 | Same loop; **If `num == candidate`** | We keep the candidate alive (`capacity++`), so we are “counting” the majority element. |
| 4 | If `num != candidate` | The counter tilts against the candidate (`capacity--`), and when it finally becomes zero, we bump to a new candidate. |
| 5 | End of loop | The candidate left is the majority in the array (the algorithm keeps finding a candidate, but the only place that is able to survive is one that occurs > n/2). |
| 6 | *(Optional)* Verify | Count how many times the candidate appears. If this count is `> n/2` we have the majority. |

> **Why does this work?**  
> Every time a non‑candidate element is seen, we pair it with a candidate element.  
> If we decrement the counter we swap `capacity` for one candidate with another element.  
> Therefore the “unmatched” vertices never have a counter.  
> The only element that can stay at the start of the process is ultimately one that appears more often than all other elements out together, i.e. a majority.
