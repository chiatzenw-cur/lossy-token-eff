The solution works **without** relying on any two‑sided `LCA` helper – it solves the problem in a single pass of the tree.

```python
# ------------------------------------------------------------------
#  Tree Node definition
# ------------------------------------------------------------------
class TreeNode:
    """A node possibly carrying a left‑ and right‑child,
    access to a parent pointer, and a value (e.g. for debug)."""
    __slots__ = ("val", "left", "right", "parent")

    def __init__(self, val, left=None, right=None, parent=None):
        self.val   = val
        self.left  = left
        self.right = right
        self.parent = parent

    def __repr__(self):
        return f"TreeNode({self.val!r})"


# ------------------------------------------------------------------
#  Helper: build a binary tree that returns the lowest common ancestor.
# ------------------------------------------------------------------
def build_tree_and_map(root, node_to_parent=None):
    """
    Recursively walk the tree from the root, setting `parent`
    pointers for every child and of course passing the parent pointer
    all along.  For an undef‑in‑place insertion we just walk the tree
    *once* – this is O(N) time, O(N) for the parent array.
    """
    if node_to_parent is None:
        node_to_parent = {}

    tree_map = {}
    for node in preorder_iter(root):
        if node.left is not None:
            node.left.parent = node
            node_to_parent[node.left] = node
        if node.right is not None:
            node.right.parent = node
            node_to_parent[node.right] = node
        node_to_parent[node] = node.parent   # <-- the node itself knows its parent here
    return node_to_parent

def preorder_iter(root):
    """Yield every node in a naive preorder fashion."""
    root_stack = []
    if root:
        root_stack.append(root)
    while root_stack:
        node = root_stack.pop()
        yield node
        if node.right:
            root_stack.append(node.right)
        if node.left:
            root_stack.append(node.left)


# ------------------------------------------------------------------
#  Main: find the highest common ancestor of two nodes in a binary tree
# ------------------------------------------------------------------
def highest_common_ancestor(node1, node2):
    """
    Return the root‑most ancestor of node1 and node2.
    If the tree contains both nodes then the path from root to `node1`
    is mapped to an array of `node1`'s ancestors.  Then the path from
    root to `node2` is walked, looking for the first node that is already
    in that array.  That node is the topmost ancestor common to both
    nodes.
    """
    if node1 is None or node2 is None:
        return None

    # 1. Build the list of all ancestors of node1 that its path
    #    to the root contains (including the node itself itself).
    #    List is built from the maximum depth downwards: we can keep
    #    a bitset or dictionary to map the node->index.
    inner_set_for_node1 = set()
    cur = node1
    while cur:
        inner_set_for_node1.add(cur)
        cur = cur.parent

    # 2. Walk from node2 up to the root; the first node that is already in
    #    first path's ancestor set is also the topmost ancestor.
    #    This is guaranteed to maintain root‑first sense: it is the
    #    highest ancestor from the starting loop.
    cur = node2
    while cur:
        if cur in inner_set_for_node1:
            return cur
        cur = cur.parent

    return None   # In case both nodes are not in the same tree
```

### How it works

1. **Building a parent pointer** – `build_tree_and_map()` takes the root (you can also pass a list of nodes that suffices for the assignment) and guarantees that every node knows its parent in a single pass (this is the canonical “parent‑pointer” trick – O(N) time, O(N) memory).

2. **Collecting ancestor set** – The `281..` helper says:  
   *“Walk from `node1` to the root, collect every node in one set; this is the complete set of ancestors for node1 (including itself).”*

3. **Scanning the other chain** – For `node2`, we walk X‑scale up until we reach a node whose identity is already in the set.  
   Because we walk **once** from the deepest node up to the root, the first encountered node is **the deepest one common to both**.  
   In a tree, that *any* descendant is the deepest; the *closest* one is obviously the **top‑most** ancestor.  
   Therefore the node returned by the above algorithm is the **maximum‑height** ancestor – that is, the **highest** common ancestor.  

4. **Handling disjoint trees** – In case the two nodes belong to disconnected trees, a guard is returned (`None`).

### Complexity

| Operation | Time | Space | Remarks |
|-----------|------|-------|---------|
| Building node‑to‑parent by `preorder_iter` | O(N) | O(N) | One‑time cost in the tree (or per query if you want to reuse them). |
| Finding *ancestor set* of node1 | O(depth1) | O(depth1) | Stored in `inner_set_for_node1`. |
| Walking from node2 up to the root | O(depth2) | O(1) | Keeps track of the “current” ancestor. |

Thus the overall time complexity is **O(N + depth1 + depth2)** and the usual linear‑time
algorithm for the height of the **LCA** problem is maintained; nevertheless, it is the short‑form version that “skips the LCA and returns the *highest* one alphabetically”.
