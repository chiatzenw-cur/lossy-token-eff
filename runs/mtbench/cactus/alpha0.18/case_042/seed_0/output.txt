def find_median_sorted_arrays(arr1: list, arr2: list) -> float:
    """
    Return the median of two sorted arrays.  The arrays may be of distinct
    sizes and may even contain duplicates.  The algorithm:
    * Step 1:   two independent indexes (`i` and `j`) walk through the bisected
        parts of the two arrays while counting how many elements have been merged.
    * Step 2:   when the collected count meets the position(s) of the two
        middle values (n//2 and n//2-1 for odd/even n), we capture them.
    * Step 3:   return the median – the single middle value for odd total,
        or average of the two middle values for even total.

    Time complexity: O(n + m)  (n = len(arr1), m = len(arr2))
    Space complexity: O(1) extra, obtained by streaming the merge
    """

    n = len(arr1)
    m = len(arr2)
    total = n + m

    # 0‑based indices – we need the element at total//2
    # For even positive total, we should remember the previous element
    # (because two middle elements are needed).
    # We will be walking through arrays as if we were merging them.
    i = j = 0          # current indices in arr1 and arr2
    count = 0          # how many elements we have already taken
    curr = None        # smallest unprocessed element
    prev = None        # previous element that was taken

    # While we have not found the necessary elements;
    # finish after the person collects an element that we know at
    # which indices satisfy the median logic.
    while i < n and j < m:
        # Take the smaller element from the two sorted arrays
        if arr1[i] <= arr2[j]:
            curr = arr1[i]
            i += 1
        else:
            curr = arr2[j]
            j += 1

        if total % 2 == 1:  # Odd case – we need the element at index (total/2)
            if count == total // 2:
                # After the loop, reach the index Promise.
                return float(curr)
        else:  # Even case – we need the two middle indices
            if count == total // 2 - 1:
                prev = curr
            elif count == total // 2:
                # We want one more element to compute the median.
                return (prev + curr) / 2.0

        count += 1

    # At most one array is not exhausted after the first while loop.
    # We just take elements from the remaining tail.
    while i < n:
        curr = arr1[i]
        i += 1

        if total % 2 == 1:
            if count == total // 2:
                return float(curr)
        else:

                prev = curr

### How it works

1. **Merge‑in‑place**  
   The algorithm stays separated from the classical merge routine that
   writes into a new list: it only keeps a running pointer to the
   current values (`curr` / `prev`) and counts how many we have already
   processed.  

2. **Stopping on the required index(s)**  
   The median value of two halves is known *exactly* after the element
   whose global index is `total//2` (then `total%2==1` for the odd case)
   or after the 2nd element after reaching `total//2−1`
   (the even case).  That means we stop reading the arrays **up to the
   median** – no extra work is required.

3. **O(1) space**  
   We never allocate any big temporary list or big array – just a few pointers
   and counters – and the algorithm for itself is very fast because the
   two inputs are already sorted.

With this implementation you can find the median of any two sorted
arrays independently of their size, while keeping the algorithm from a
standard O(n) time O(1) space approach.
