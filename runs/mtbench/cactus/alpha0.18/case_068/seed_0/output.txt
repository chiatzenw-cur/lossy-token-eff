## Determine the problem (at a glance)

| Description | Input | Output | Complexity |
|-------------|-------|--------|------------|
| two sorted lists `<A, m>`, `<B, n>` | `a[0 … m-1]`, `b[0 … n-1]`, integer `k` (1‑based) | value of the kth smallest element across both lists | Count `k` once – O(m+n) time, O(1) space |

The only “kth” requirement means we **don’t need to fully merge** the lists; we can stop when we’ve one‑by‑one consumed exactly `k` elements.

## Algorithm sketch

```text
i ← 0          # index into A
j ← 0          # index into B
for step = 1 … k-1:            # 1‑based loop: we need the k‑th element
    if i < m and (j >= n or A[i] < B[j]):
        i ← i + 1
    else:
        j ← j + 1
# after the loop, the next element to pick would be the k‑th
if i < m and (j >= n or A[i] < B[j]):
    return A[i]
else:
    return B[j]
```

Because `i` and `j` never advance past `k`, each step can be executed only once.  
When `k` is either `m + n` or the total length of the merged array, memory doubles:

```text
for step = 1 … k
    # ...
```

`i` and `j` increment at most `k` times, so the total work is `O(k)` but that is at most  
`O(m + n)`, because `k ≤ m + n`.

## Correctness proof (sketch)

* Variables `i` and `j` represent how many elements from `A` and `B` have already been “discarded” from consideration.  
* At each step we compare the first “active” element in each list (`A[i]` and `B[j]`).  
  *If that element is smaller (or to the left of the partially‑merged list of at most `k` elements), it cannot be the kth
  final element.*  
  Hence we advance the pointer on that list.  
* This is a classic “one‑move” comparison proof: it is exactly what happens when you merge two sorted lists, but you stop *in place* after consuming the first `k-1` elements.  
* Therefore the element chosen at the very end is precisely the smallest remaining element after the `k‑1` smallest
  overall have been removed.  
* Consequently it is the kth‑smallest element in the union.

The algorithm terminates as soon as `k` is reached; at any iteration,
`i & j` are maintained such that each index ≤ `k`.  
Hence the loop runs at most `k`, and the total time is linear in `m + n`.

## Full Python implementation

```python
from typing import List, Optional, Union

def kth_smallest(a: List[int], b: List[int], k: int) -> Optional[int]:
    """
    Return the k-th smallest element (1‑based) in the union of the sorted
    lists `a` and `b`.  If k is too large, returns None.

    Parameters
    ----------
    a : List[int]
        First sorted list (ascending).
    b : List[int]
        Second sorted list (ascending).
    k : int
        1‑based rank of the desired element.

    Returns
    -------
    Optional[int]
        the k‑th smallest value, or None if k is out of range.
    """
    m, n = len(a), len(b)

    if k <= 0 or k > m + n:
        return None

    i = j = 0      # indices into a and b
    # We initialise the 0‑based index of the next element: ``step``.
    # We will loop 0..k-2 to skip the first k-1 elements.
    for _ in range(k - 1):
        if i < m and (j >= n or a[i] <= b[j]):
            i += 1
        else:
            j += 1

    # the guaranteed element
    if i < m and (j >= n or a[i] <= b[j]):
        return a[i]
    else:
        return b[j]


# Example:
if __name__ == "__main__":
    a = [1, 3, 5, 7, 9]
    b = [2, 4, 6, 8, 10]
    for k in [1, 4, 7, 10]:
        print(f"k={k} → {kth_smallest(a, b, k)}")
```
