Given two sorted lists  

```
A[0 … m‑1]   (length m)
B[0 … n‑1]   (length n)
```

return the element that would appear in position `k` (1‑based) if the two
lists were merged.  
The algorithm should run in *linear* time in the worst case – i.e.  
`O(m + n)` (or `O(k)` if `k ≤ m + n`).

---

## Intuition

Both lists are already sorted.  
The “kth smallest” element is the element that would be found after taking
the first `k` elements of the union of the two lists.

Because the lists are sorted, we simply advance through them keeping two
pointers:

```
i – index in A
j – index in B
```

At each step we compare the two current elements.  
The smaller one is the next element in the merged order, so we advance the
corresponding pointer and decrement `k`.

When `k` becomes 1, the current list holds the kth element – it is the minimum
of the two remaining items (or the only element left if one list is exhausted).

The algorithm visits at most `k` elements of A and/or B, so the
time complexity is `O(k)` and the worst‑case (when `k = m + n`) is `O(m + n)`.

---

## Algorithm (Python‑like pseudocode)

```python
def kth_smallest(A: list[int], B: list[int], k: int) -> int:
    """
    Return the k‑th smallest element (1‑based) in the union of sorted lists A and B.
    Assumes 1 <= k <= len(A) + len(B).
    """
    i, j = 0, 0          # current indices for A and B
    while True:
        # Edge cases: one list is exhausted
        if i == len(A):
            return B[j + k - 1]          # B[k-1] from A’s perspective
        if j == len(B):
            return A[i + k - 1]

        # if k is 1, the answer is the current smaller element
        if k == 1:
            return min(A[i], B[j])

        # Compare current elements
        if A[i] <= B[j]:
            i += 1
            k -= 1
        else:   # B[j] < A[i]
            j += 1
            k -= 1
```

---

## Correctness proof

We prove that the function returns the kth smallest element.

### Lemma 1  
At any point in the loop, the set of elements that have already been
skipped (those counted by the number of increments of `i` and `j`) is exactly
the same as the first `k_initial - k_current` elements of the union of the two
lists (where `k_initial` is the original k).

*Proof.*  
Initially `i = j = 0`, `k_current = k_initial`.  
Assume the lemma holds before an iteration.  
If `A[i] <= B[j]`, we advance `i` (skipping `A[i]`) and decrement `k`.  
`A[i]` was the smallest among the remaining union elements, so it is indeed
first in the merged order, and we “removed” it.  
The same reasoning applies for the case `B[j] < A[i]`. ∎



### Lemma 2  
When the loop terminates, the element returned is the smallest of the
remaining elements (those not yet skipped).

*Proof.*  
There are two termination conditions:

1. **`i == len(A)`** – All elements of `A` have been skipped.
   The remaining elements are the suffix of `B` starting at `j`.  
   The element at position `j + k - 1` in `B` is the `k`‑th smallest in the
   remaining set, because `k` counts how many smaller objects we still need.

2. **`j == len(B)`** – Symmetric to case 1.

3. **`k == 1`** – Means we have skipped all but one element of the union.
   The current minimum of `A[i]` and `B[j]` is therefore that remaining
   element. ∎



### Theorem  
`kth_smallest(A, B, k)` returns the k‑th smallest element in the union of
`A` and `B`.

*Proof.*  
By Lemma 1, after each iteration we have correctly removed the smallest
elements of the remaining union.  
When the loop stops, exactly `k_initial - k_current` elements have been removed,
and the rest are the remaining elements.  
By Lemma 2, the element returned is the minimum of the remaining elements,
exactly the `k_current`‑th smallest, which equals the `k_initial`‑th smallest
of the whole union. ∎



---

## Complexity analysis

*Time* – In each iteration we advance exactly one pointer and decrement `k`.  
Thus the maximum number of iterations is `k_initial`.  
Worst case: `k_initial = m + n`, so `O(m + n)`.

*Space* – Only constant extra variables (`i`, `j`, `k`).  
Space complexity is `O(1)`.

## Example

```python
A = [1, 3, 5, 7]
B = [2, 4, 6, 8, 9]
k = 5

# The merged order: 1, 2, 3, 4, 5, 6, 7, 8, 9
# The 5th smallest element is 5

print(kth_smallest(A, B, k))   # → 5
```

The algorithm performs at most 5 iterations, each comparing a pair.

## Practical notes

* **1‑based vs 0‑based** – The implementation above accepts `k` as 1‑based.
  If you prefer 0‑based indexing, change the conditions to `n == 0` and
  `return B[j]` / `return A[i]` when `k == 0`.

* **Large inputs** – For very small `k` (e.g., `k = 10`) the runtime is
  `O(k)` – often far faster than a full merge.  
  For `k` close to `m + n`, this becomes a full merge of the two lists.

* **Alternative (logarithmic)** – A more sophisticated algorithm exists
  that runs in `O(log(min(m,n)))` time, but it is more complex for
  this problem’s stated requirement of linear complexity.
