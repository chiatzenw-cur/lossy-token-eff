The solution sorts the two input arrays in‑place and then walks through them with two indices – a classic “merge” trick – printing (or storing) each element that appears in both arrays.  
All helpers are simple integers; we never create a new data‑structure proportional to the input size.

> **Why this works:**  
> *Sorting* turns the two arrays into increasing sequences.  
> *Two‑pointer traversal* is then able to look at the "current" smallest element of each array and move the pointer that is holding the smaller value forward.  
> Whenever the two values are equal, we have hit a common element and we can output it (or log it).  
> Because each array is scanned only once, this algorithm runs in `O(n log n + m log m)` time (the cost of sorting) and `O(1)` extra space.

## 1.  Python Implementation

```python
def find_common(a, b):
    """
    Print (or collect) the common elements of two arrays in sorted order.
    No extra data structures are used besides the input arrays themselves.
    """
    # In‑place sort of the two arrays
    a.sort()
    b.sort()

    i, j = 0, 0   # two pointers

    while i < len(a) and j < len(b):
        if a[i] == b[j]:
            # Found a common element; print it (or collect)
            print(a[i], end=' ')
            i += 1
            j += 1
        elif a[i] < b[j]:
            i += 1
        else:   # a[i] > b[j]
            j += 1

    print()  # newline after finishing

# Demo
if __name__ == "__main__":
    arr1 = [1, 5, 9, 10, 11, 15]
    arr2 = [2, 4, 5, 6, 7, 10, 12]
    print("Common elements:")
    find_common(arr1, arr2)
```

**Output**

```
Common elements:
5 10
```

## 2.  C++ Implementation (no extra containers)

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

void print_common(std::vector<int>& a, std::vector<int>& b) {
    std::sort(a.begin(), a.end()) ;
    std::sort(b.begin(), b.end()) ;

    size_t i = 0, j = 0;
    while (i < a.size() && j < b.size()) {
        if (a[i] == b[j]) {
            std::cout << a[i] << ' ';
            ++i; ++j;
        }
        else if (a[i] < b[j]) {
            ++i;
        }
        else {
            ++j;
        }
    }
    std::cout << '\n';
}

int main() {
    std::vector<int> A1{1, 5, 9, 10, 11, 15};
    std::vector<int> A2{2, 4, 5, 6, 7, 10, 12};

    std::cout << "Common elements: ";
    print_common(A1, A2);
}
```

**Output**

## 3.  Why This Meets the “No Extra Data Structures” Requirement

| Approach | Extra Data Structures Used? | Reason | 
| -------- | --------------------------- | ------ |
| Sorting in‑place (functions `sort` / `std::sort`) | No (the sort itself is in‑place) | The algorithm only rearranges the input array – the memory footprint is `O(1)` besides `O(log n)` stack used by quicksort. |
| Two‑pointer traversal | No | Only two integer indices (`i` and `j`) are used. |
| Printing | No | The output is printed directly; the program never prints into a temporary container. |

If you prefer to *collect* the common elements instead of printing them, you can replace the `print` / `cout` call with a `std::vector<int> result`, but that would be an **extra data structure** and would violate the pure “no extra data structures” constraint.

## 4.  Alternative (Brute‑Force) When N and M are Small

If your arrays are tiny and you simply want a *proof of concept* that does not use *any* extra data structures, a nested loop works:

```python
def find_common_brute(a, b):
    for x in a:
        for y in b:
            if x == y:
                print(x, end=' ')
```

This runs in `O(n·m)` time, still uses only integer variables, and obeys the constraint.  
For large arrays, however, the sorted‑two‑pointer method is preferred.
