When both arrays are of different sizes we can still obtain the median simply by
merging them *in order* until we reach the middle element(s).  
Because we do not need the full merged array, we can keep just two
variables – the last two values that were “seen” – and stop as soon as we get
the median.  
This yields

* **Time** – we scan at most `m + n` elements: `O(m+n)`  
* **Space** – only a handful of integer variables: `O(1)`  

(We use the standard integer linear scan; no recursive calls, no extra arrays.)

---

### Algorithm

```
findMedianSortedArrays(a, b):
    i = 0                     // index in a
    j = 0                     // index in b
    total = len(a) + len(b)
    count = 0                 // elements processed so far
    prev = 0                  // previous element in the merged order
    curr = 0                  // current element in the merged order

    while count < total / 2 + 1:
        // choose the next smallest element
        if i < len(a) and (j >= len(b) or a[i] <= b[j]):
            curr = a[i]
            i++
        else:
            curr = b[j]
            j++

        prev = curr
        count++

    // total is odd – the median is the current value:
    if total % 2 == 1:
        return prev

    // total is even – the median is average of the two middle values:
    // `prev` holds the element at index total/2
    // `curr` holds the element at index total/2 + 1.
    // Because we stop exactly after the second of the two middle elements,
    // `prev` is the first middle and `curr` is the second middle.
    return (prev + curr) / 2.0
```

### Correctness Proof  

We prove that the algorithm returns the true median of the two sorted lists.

1. **Invariant**  
   After each iteration of the loop, `prev` and `curr` are the last two items
   in the *merged* order of the first `count` elements of the two arrays.  
   *Proof of invariant*:  
   *Initialization*: before the first iteration `count = 0`, `prev` and `curr`
   are undefined, but the invariant vacuously holds.  
   *Maintenance*: at each iteration we pick the smaller of the two
   taken‑from‑next elements (standard merge logic).  
   This newly chosen element becomes the new `curr`.  
   The previous `curr` becomes `prev`.  
   Hence `prev` and `curr` are now the last two items in the merged order. ∎

2. **Termination**  
   The loop stops when `count == total / 2 + 1`.  
   Since `total = m+n`, we have processed exactly the first half of the
   merged array plus one additional element – i.e. the element that occupies
   the exact middle (or second middle) position in the resulting sorted array.

3. **Odd-length case**  
   If `total` is odd, the median is the element at position `total/2`
   (0‑based).  
   The loop stops exactly when `count` equals that position plus one,
   giving `curr` the median value.  
   The algorithm returns `prev` (after the loop `prev` equals `curr`
   because `prev` was updated before the last increment).  
   Thus the returned value is the true median.

4. **Even-length case**  
   If `total` is even, the median is the average of the two middle values
   at positions `total/2 - 1` and `total/2`.  
   The loop terminates after the second middle element has been processed.
   By the invariant, `prev` holds the first middle element and `curr`
   holds the second middle element.  
   The algorithm returns `((prev + curr) / 2.0)`, which is exactly the
   definition of the median for even-length arrays.

Since in all cases the algorithm returns the correct median, the algorithm
is correct.

* **Time** – In each iteration we advance either `i` or `j`, thus at most

  Hence `O(m + n)`.

* **Space** – Only a fixed number of integer/double variables are used:
  `i, j, count, prev, curr, total`.

### Reference Implementation (Java 17)

```java
public class MedianOfTwoSortedArrays {

    /**
     * Finds the median of two sorted arrays (ascending).  The arrays may
     * have different sizes.  The algorithm runs in O(n) time and uses O(1)
     * extra space.
     *
     * @param a first sorted array
     * @param b second sorted array
     * @return median of the two arrays
     */
    public static double findMedianSortedArrays(int[] a, int[] b) {
        int i = 0, j = 0;
        int total = a.length + b.length;
        int count = 0;
        int prev = 0, curr = 0;     // will hold the two middle elements

        // we need only the first half of the merged array plus one more element
        int required = total / 2 + 1;   // e.g. 7 elements -> 4th element

        while (count < required) {
            // choose which array to take next
            if (i < a.length && (j >= b.length || a[i] <= b[j])) {
                curr = a[i++];
            } else {
                curr = b[j++];
            }
            prev = curr;
            count++;
        }

        // odd total length ⇒ median is the middle element
        if (total % 2 == 1) {
            return prev;
        }

        // even total length ⇒ median is average of the two middle elements
        // prev holds the element at index total/2 - 1
        // curr holds the element at index total/2
        return (prev + curr) / 2.0;
    }

    // ---------- Simple test harness ----------
    public static void main(String[] args) {
        int[] a = {1, 3, 8};
        int[] b = {7, 9, 10, 11};

        System.out.println("Median: " + findMedianSortedArrays(a, b));
        // Expected: 7.5
    }
}
```

**Explanation of the test**

* `a = [1, 3, 8]` (length 3)  
* `b = [7, 9, 10, 11]` (length 4)  
* Total length = 7 (odd) → median is the 4th element after merging:  
  `[1, 3, 7, 8, 9, 10, 11]` → median `8`.
