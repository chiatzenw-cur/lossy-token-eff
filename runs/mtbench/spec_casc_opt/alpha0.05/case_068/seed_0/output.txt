Given two already‑sorted lists **A** and **B** such that  
`A = [a1, a2, …, am]` and `B = [b1, b2, …, bn]` (both sorted in ascending order) the task is to return the *k smallest* element in the union of the two lists.

The classic “merge” step of merge‑sort gives us an optimal *linear* pass: we walk through `A` and `B` once, always taking the smaller of the two current elements, and we stop when we have seen `k` elements.  
Because we never look again at an element of any list, the value of the `k`‑th element is found in **O(k)** time, and in the worst case (when `k = m+n`) we reach **O(m+n)** time.

> **Why linear?**  
> The merge operation itself is a single linear pass through both lists.  
> The algorithm does **not** employ any logarithmic search or binary search, so it stays in the linear world.

## Algorithm (Python‑style pseudocode)

```python
def kth_smallest(A, B, k):
    """
    Return the k-th smallest element of the union of the sorted lists A and B.
    
    Pre‑conditions:
        - A and B are sorted in non‑decreasing order
        - k is 1‑based: i.e., k = 1 refers to the smallest element
        - 1 <= k <= len(A) + len(B)
    """
    i = j = 0            # current indices in A and B
    count = 0            # how many elements we have 'used' so far
    answer = None

    while i < len(A) and j < len(B):
        if A[i] <= B[j]:
            current = A[i]
            i += 1
        else:
            current = B[j]
            j += 1

        count += 1
        if count == k:
            answer = current
            break

    # If one list is exhausted, the answer is in the remaining part
    if answer is None:
        # j or i has reached the end of its array
        if i == len(A):
            # It must be in B
            answer = B[j + k - 1]          # k - 1 picks the (k‑th) element
        else:
            # It must be in A
            answer = A[i + k - 1]

    return answer
```

### Complexity

* **Time** – In the most common case we stop when the `k`‑th element is found, so the loop runs `k` times.  
  In the worst case (`k = m+n`) the loop runs `m+n` times → **O(m+n)**.

* **Space** – The algorithm uses only a few integer counters → **O(1)**.

## Edge‑Case & Edge‑Case Handling

| Edge case | What happens | Why it’s safe |
|-----------|--------------|---------------|
| `k = 1` (smallest element) | We compare the first elements of each list; then we either return `A[0]` or `B[0]`. | We only interpret the first element. |
| `k = m+n` (largest element) | The loop finishes when the end of both lists is exhausted; we then return the last element of the remaining list. | The formula `answer = B[j + k - 1]` (or `A[i + k - 1]`) works because `k-ball` steps are still inside the list. |
| One list empty | The inner loop never runs because the corresponding condition is false. We test `if i == len(A)` (or `j == len(B)`) to pick the remaining element. | No comparison with an empty list is ever attempted. |
| Elements equal across lists | The algorithm uses `<=` comparator, so ties are consistently taken from the list that is currently being inspected. | The caller doesn’t care about equal elements; they will still be counted correctly. |
