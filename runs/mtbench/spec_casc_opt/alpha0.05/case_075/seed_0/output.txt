**Machine learning (ML)** is a subfield of artificial intelligence that focuses on building algorithms that can understand, learn from, and make predictions or decisions based on data.  
Instead of training a model by hand‑coding rules (or writing a “rule‑based” system), a machine‑learning system is *trained* on data: it learns a mapping from input data (features) to predictions or actions. The rules are learned automatically from the data, not by a human programmer.

Key steps in a typical ML pipeline:

| Step | Goal |
|------|------|
| **Input** | Collect raw data (images, sensor readings, click logs, etc.) |
| **Feature extraction** | Convert raw data into a set of features (variables/attributes) that the algorithm can understand. |
| **Model** | Choose a mathematical structure – e.g., a neural network, a support vector machine, a decision tree, etc. |
| **Training** | Optimize parameters (weights) of the model so that the loss/error between examples and predictions is minimized. |
| **Evaluation** | Test the model on unseen data to estimate how well it will generalize. |
| **Deployment** | Apply the trained model to new data in production. |

ML is **data‑driven**: the quality of the data, the representativeness of the training examples, and the quantity of data can all be used to measure performance. ML is supplemented by numerous sub‑fields—deep learning, reinforcement learning, Bayesian methods, etc.—but the core idea remains the same: *learn from data and improve over time.*

### 2.1 Supervised Learning

**How it works**

- **Data**: A set of training examples `[(x₁, y₁), (x₂, y₂), …]`.
- **Goal**: Learn a function `f(X) ≈ Y` that predicts `y` from new `x`.
- **Loss Function**: Measures how far the model’s predictions are from the true labels.
- **Optimization**: Minimize loss over training data using gradient descent, etc.

**Real‑world examples**

| Domain | Example |
|--------|---------|
| **Medical diagnosis** | A *class of disease* from a patient’s images or test results. |
| **Finance** | Predicting a *stock value* (regression) or *price movement* (regression). |
| **Computer vision** | Spotting a cat in a photo (image classification). |
| **Natural language processing** | Sentiment analysis: review → positive/negative. |
| **Speech** | Voice recognition: audio ↔ text. |

---

### 2.2 Unsupervised Learning

**How it works**

- **Data**: Just the unsupervised dataset `X = [x₁, x₂, …]`.
- **Goal**: Discover *patterns* or *structure* that humans can interpret or that can help downstream tasks among them.
- **Common Algorithms**:  
  - **Clustering**: K‑Means, Silhouette, DBSCAN, Hierarchical clustering.  
  - **Density Estimation**: Kernel density estimation.  
  - **Dimension Reduction**: PCA, t‑SNE, UMAP.  
  - **Association Mining**: Apriori, FP‑Growth (“people who bought A also bought B”).  

**Real‑world examples**

| Domain | Example |
|--------|---------|
| **Marketing** | Customer segmentation for targeted advertising. |
| **Customer support** | Organising large FAQ transcripts into common theme clusters. |
| **Image processing** | Grouping images by similar visual style (e.g., style‑transfer research). |
| **Anomaly detection** | Detecting network intrusions by spotting outlier patterns. |
| **Recommender systems** | Discovering “latent user groups” that share some latent preferences. |

---

### 2.3 Reinforcement Learning (RL)

**How it works**

- **Data**: RL is **not** typically high‑dimensional data in the sense of a static dataset. The agent interacts with an **environment** (a game, a robot, a simulator).
- **Sequenced Action**: At each step `t`: observe state `s` → take action `a` → receive next state `s’` and reward `r′`.
- **Goal**: Learn a policy `π(a|s)` that maximizes expected cumulative reward over time (often discounted).

**Real‑world examples**

| Domain | Example |
|--------|---------|
| **Gaming** | AlphaGo‑Zero, AlphaStar, DOTA. |
| **Robotics** | Wrist‑based pick‑and‑place, legged robot walking. |
| **Autonomous vehicles** | Traffic control for self‑driving cars, lane‑keeping. |
| **Finance** | Trading strategy, arbitrage. |
| **Recommendation** | Real‑time ad placement, content recommendation. |

## 3. Key Differences in Practice

| Feature | Supervised | Unsupervised | Reinforcement |
|---------|-------------|--------------|--------------|
| Label requirement | Yes | No | No |
| Primary Objective | Predict *Y* | Discover *Y* structure | Maximize *R* over act |
| Rewards / Feedback | None | None | Event‑based reward |
| Data Volume | Must cover ground truth | More flexible; may rely on unlabeled | Requires episodes / repeated tasks |
| Common Models | Neural nets, SVM, decision trees | Clustering, embeddings, self‑supervised | Policy networks (deep nets), Q‑learning |
| Evaluation | Accuracy, MSE | Silhouette, correlation, externalized | Cumulative reward, reward‑maximizing full reward |
| Next‐Actions | No direct mapping | Clustering or learned transformations | Policy or value functions guide actions |

## 5. Concluding Remarks

- **Unified View**: Though ML is a *broad* field, the core principle is the same: *learn a mapping,* *don’t program hard‑coded rules.*  
- **Supervised** shines when we have *high‑fidelity, labeled data* where the majority of the problem is precise classification or regression.  
- **Unsupervised** is indispensable when we need to explore the *feature space* or *detect hidden patterns* without labels, often in marketing or anomaly detection.  
- **Reinforcement** takes the game to humans or robotics: The agent has *a goal, a sequence of actions and rewards*, and learns to *increase* its goals over time.  
- In practice, many new approaches combine *specialization* and *retrieval* (e.g., supervised, unsupervised, RL and *self‑supervised* for data without explicit labels).

- Future developments (e.g., *self‑supervised* learning, *contrastive learning*, and *multi‑policy RL*) blur the lines between these categories, but the core distinctions remain foundational for understanding the design, training, and deployment of ML methods.
