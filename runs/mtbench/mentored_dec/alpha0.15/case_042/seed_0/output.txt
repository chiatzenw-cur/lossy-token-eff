It follows the classic “merge‑up‑to‑median” idea – we walk the two arrays once, picking the smaller of the two current elements at every step.  
Only two integer variables (`i`, `j`) and a counter (`count`) are required, so the algorithm uses **O(1) additional space**.  
Each element is inspected at most once ⇒ **O(n)** time, where `n = len(A)+len(B)`.

```python
def findMedianSortedArrays(A, B):
    """
    Return the median of two sorted arrays A and B.

    Parameters
    ----------
    A : list[int] or list[float]
        First sorted array (may be empty).
    B : list[int] or list[float]
        Second sorted array (may be empty).

    Returns
    -------
    float
        The median value.  For an odd total length it is the middle element;
        for an even total length it is the average of the two middle elements.
    """
    m, n = len(A), len(B)
    total = m + n

    # Handle corner case where both arrays are empty
    if total == 0:
        raise ValueError("Both arrays are empty – median undefined.")

    # If one array is empty, simply return its median
    if m == 0:
        if n % 2 == 1:
            return B[n // 2]
        else:
            return (B[n // 2 - 1] + B[n // 2]) / 2.0
    if n == 0:
        if m % 2 == 1:
            return A[m // 2]
        else:
            return (A[m // 2 - 1] + A[m // 2]) / 2.0

    i = j = 0          # indices for A and B
    count = 0          # how many elements we've "seen" so far
    prev2 = prev1 = None  # keep the two most recent values

    # We only need to step through until we reach the middle
    target = total // 2   # index of median (0‑based) in the merged array
    # For even total we need the two middle indices: target and target-1

    while count <= target:
        prev2 = prev1                   # shift the two saved numbers
        # Determine next element (select the smaller one)
        if i < m and (j >= n or A[i] <= B[j]):
            prev1 = A[i]
            i += 1
        else:
            prev1 = B[j]
            j += 1
        count += 1

    # After the loop:
    #   - if total is odd, prev1 is the median
    #   - if total is even, prev2 and prev1 are the two middle elements
    if total % 2 == 1:
        return float(prev1)
    else:
        return (prev2 + prev1) / 2.0
```

### How it works

| Step | What it does | Why it works |
|------|--------------|--------------|
| `count <= target` loop | Walks through the two arrays one element at a time, always picking the smaller remaining element. | Like the merge step of merge‑sort, but we stop as soon as we reach the middle position. |
| `prev2`, `prev1` | Keep the last two values that were pulled from either array. | For even total length we need the two middle numbers; for odd we only need the current one. |
| Final `if total % 2 == 1` | Case distinction between odd and even overall length. | Median definition differs accordingly. |

### Example usage

```python
>>> findMedianSortedArrays([1, 3, 8], [7, 9, 10, 11])
8.0          # total 7 elements → odd → median is 8

>>> findMedianSortedArrays([1, 2], [3, 4, 5, 6])
3.5          # total 6 elements → even → (3 + 4)/2 = 3.5
```

### Complexity

* **Time** – Each element of the two arrays is examined at most once → **O(m + n)**, where `m` and `n` are the lengths of the arrays.  
* **Space** – Only a handful of integer variables → **O(1)** auxiliary space.
