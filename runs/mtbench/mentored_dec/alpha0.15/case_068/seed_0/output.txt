Given two sorted lists `a` (size `m`) and `b` (size `n`), return the *k*‑th smallest element in the union of `a` ∪ `b` (1‑based indexing).  
The only allowed operations are comparisons and indexing; we must not sort the union.

---

### 1.  Why a linear algorithm works

Both lists are already sorted.  
If we merge them the way we would merge two runs in merge‑sort, the elements we encounter from left to right are exactly the elements of the union in sorted order.  
Since we only need the first *k* elements of that merged sequence, the work we perform is essentially *k* comparisons – at worst we merge the whole pair, i.e. O(*m* + *n*).  
Thus the algorithm runs in linear time (Θ(min(*k*, *m* + *n*))).

---

### 2.  Algorithm (two‑pointer merge)

```
i ← 0          # index into a
j ← 0          # index into b
cnt ← 0        # how many elements of the merged list we have seen

while cnt < k:
    if i == m:
        # a exhausted => take from b
        answer ← b[j]
        break
    elif j == n:
        # b exhausted => take from a
        answer ← a[i]
        break
    else:
        if a[i] <= b[j]:
            answer ← a[i]
            i ← i + 1
        else:
            answer ← b[j]
            j ← j + 1
    cnt ← cnt + 1

return answer
```

*If* `k` is larger than `m+n`, the function should raise an exception or return `None`.  
If the lists contain duplicate values, the algorithm preserves the required multiplicity.

---

### 3.  Correctness proof (sketch)

We prove by induction that after the while‑loop terminates, `answer` is the *k*‑th smallest element.

*Base:*  
Before the first iteration (`cnt = 0`) the invariant holds trivially: the first `cnt` items of the merged list are the smallest `cnt` elements of the union.

*Inductive step:*  
Assume after `cnt` iterations `answer` is the `cnt`‑th smallest element.  
In the next iteration we compare the smallest unused elements of each list (`a[i]` and `b[j]`).  
The smaller of the two is the next element in the merged sequence.  
We assign it to `answer` and increment the pointer of the list from which we took it.  
Thus the invariant is preserved for `cnt+1`.  

When `cnt` becomes `k`, the loop stops, and `answer` holds the *k*‑th smallest element.

---

### 4.  Complexity analysis

* **Time** – At most `k` comparisons are made (`k` may be as large as `m+n`).  
  \[
  T(m,n,k)=\Theta(\min(k,\;m+n))
  \]
  In the worst case (`k = m+n`) we traverse every element once → O(*m* + *n*).

* **Space** – Only a constant number of integer variables → O(1) auxiliary space.

### 5.  Reference implementation (Python 3)

```python
from typing import List, Optional

def kth_smallest(a: List[int], b: List[int], k: int) -> Optional[int]:
    """
    Return the k-th smallest element (1‑based) in the union of two sorted lists a and b.
    If k is out of bounds, return None.
    """
    m, n = len(a), len(b)
    if k < 1 or k > m + n:
        return None

    i = j = cnt = 0
    while cnt < k:
        # One of the lists is exhausted
        if i == m:
            return b[j + (k - cnt - 1)]
        if j == n:
            return a[i + (k - cnt - 1)]

        # Pick the smaller of the two current elements
        if a[i] <= b[j]:
            val = a[i]
            i += 1
        else:
            val = b[j]
            j += 1

        cnt += 1

    return val
```

**Examples**

```python
>>> kth_smallest([1, 5, 9], [2, 3, 7, 10], 4)
5          # 1,2,3,5...
>>> kth_smallest([1, 4], [2, 3, 5, 6], 6)
6
>>> kth_smallest([], [1, 2, 3], 2)
2
```

The function can be used in any language that supports indexed lists/arrays; the logic remains identical.
