You are given two sorted arrays (or lists) `A` and `B` of lengths `m` and `n`, respectively.  
For a given integer `k` (1‑based, i.e. `k = 1` is the smallest element in the union), return the **k‑th smallest element** in the union of the two lists.

You must do it with *linear* time – i.e. `O(m + n)` in the worst case (or `O(k)` if you prefer to count only the work done until you find the answer).  
No sorting, no heap usage, no extra `O(m+n)` auxiliary data structures.

---

## Idea – Two‑pointer merge

The two lists are already sorted.  If we merge them one element at a time (like the merge step of merge‑sort) we only need to keep a pointer into each list.  
When we have examined `k-1` elements we just return the next element; that is the `k`‑th smallest.

Because we only advance a pointer when we “consume” an element, we will never move past more than `m+n` elements.  Therefore the time complexity is `O(m + n)` and the memory usage is `O(1)`.

---

## Correctness Proof  

We prove that the algorithm returns the k‑th smallest element of the multiset  
`U = A ∪ B` (elements are considered with multiplicity, as in a normal merge).

### Lemma 1  
At every step of the algorithm, the variables `i` and `j` point to the first **unprocessed** elements of `A` and `B`.  
Initially `i = 0`, `j = 0`; after each “consume” we increment only the pointer of the list whose element was taken, so the property is preserved.

### Lemma 2  
Let `C` be the list of elements already consumed so far.  
`C` contains exactly the `t` smallest elements of `U`, where `t` is the number of consumed elements (i.e., `t` equals the number of iterations of the loop).  
Proof by induction:  
*Base*: `t=0`, `C` is empty, which is the correct set of 0 smallest elements.  
*Induction step*: Assume the lemma holds after `t` iterations.  
At iteration `t+1` we compare `A[i]` and `B[j]`.  
By the induction hypothesis all elements of `A[0..i-1]` and `B[0..j-1]` are already in `C` and are the `t` smallest of `U`.  
The next smallest element among the remaining ones is `min(A[i], B[j])`.  
That value is appended to `C`.  
Thus the invariant holds for `t+1`. ∎

### Lemma 3  
When the loop stops, `k-1` elements have been consumed and they are the smallest `k-1` elements of the union.  
Therefore the element that the algorithm returns is the `k`‑th smallest element.

*Proof.*  
The loop stops only in two cases:  
1. One of the arrays is exhausted (`i==m` or `j==n`) or  
2. We have consumed exactly `k-1` elements.  

If the loop terminates because one array ran out, the remaining `k-1` elements are in `C`, and the next element in the other array (or the rest of the remaining array) is directly the `k`‑th smallest.  
If we stop because we have consumed `k-1` elements, we still have not yet consumed the `k`‑th smallest – that is the next element in the union, which is exactly the value we output. ∎

### Theorem  
The algorithm returns the correct `k`‑th smallest element of the union of the two sorted arrays.

*Proof.*  
By Lemma 3 the algorithm’s return value is precisely the `k`‑th smallest element. Therefore it is correct. ∎

---

## Complexity Analysis

*Time* – Each iteration of the loop advances exactly one pointer (either `i` or `j`).  
Thus at most `m + n` iterations are performed, and the loop body has `O(1)` work.  
Hence the total running time is `O(m + n)` (worst‑case) or `O(min(k, m+n))` (exactly `O(k)` when `k < m+n`).

*Space* – Only a few integer variables (`i`, `j`, `k`, and temporary values) are used.  
Therefore the space complexity is `O(1)`.

## Reference Implementation (Python)

```python
def kth_smallest(A, B, k):
    """
    Return the k-th smallest element in the union of two sorted lists A and B.
    k is 1‑based:   k == 1 returns the smallest element.
    Assumes 1 <= k <= len(A)+len(B).
    """
    m, n = len(A), len(B)
    i, j = 0, 0          # indices into A and B

    # Consume elements until k-1 of them are taken.
    while i < m and j < n and k > 1:
        if A[i] <= B[j]:
            i += 1
        else:
            j += 1
        k -= 1

    # If we never exhausted one array, the next element is min(A[i], B[j]).
    if i == m:
        # A is exhausted, result is in B[j + k - 1]
        return B[j + k - 1]
    if j == n:
        # B is exhausted, result is in A[i + k - 1]
        return A[i + k - 1]
    # Otherwise both arrays have elements, choose the smaller one
    return min(A[i], B[j])
```

## Variations & Extensions

| Variant | Complexity | Typical Use‑Case |
|---------|------------|-----------------|
| **Binary‑search (O(log(min(m,n)))** | Very fast for *very* large `m` and `n` | When you’re willing to use more complex code and you want the theoretical optimum |
| **Using heap** | `O(k log 2)` (i.e. `O(k)`) | If you can use a priority queue, but you still want `O(k)` time |
| **Generalized for *t* sorted lists** | `O(t * k)` (simple merge) | If the number of lists is small, a straightforward merge is fine |

For the specific requirement of **linear* time** the two‑pointer algorithm above is the simplest, most memory‑efficient solution.
