We only need the *k‑th* smallest value from the union of the two sorted arrays.  
If we actually merge the two lists we would pay `O(m+n)` time and `O(m+n)` memory.  
We can avoid the merge by walking through the two lists in lock‑step and stopping as soon as we have seen the first `k` elements.  
The process is identical to the “merge” step of Merge‑Sort, but we stop at the `k`‑th element.  
This uses only `O(1)` extra space and at most `k` comparisons – thus `O(k)` time, which is *linear* in the worst case (`k = m+n`).

### Algorithm (Python)

```python
def kth_smallest(a: list, b: list, k: int):
    """
    Return the k‑th smallest element of the union of two sorted lists a and b.
    The lists are sorted in ascending order.
    k is 1‑based: 1 ≤ k ≤ len(a)+len(b).

    Raises ValueError if k is out of bounds.
    """
    m, n = len(a), len(b)

    if k < 1 or k > m + n:
        raise ValueError("k must be between 1 and m+n")

    i, j = 0, 0            # indices in a and b
    count = 0              # how many elements have been seen

    # Step 1 – walk through both lists while neither is exhausted
    while i < m and j < n and count < k:
        if a[i] <= b[j]:
            candidate = a[i]
            i += 1
        else:
            candidate = b[j]
            j += 1
        count += 1
        if count == k:          # we found the k‑th element
            return candidate

    # Step 2 – one list is exhausted – take from the remaining list
    while i < m and count < k:
        candidate = a[i]
        i += 1
        count += 1
        if count == k:
            return candidate

    while j < n and count < k:
        candidate = b[j]
        j += 1
        count += 1
        if count == k:
            return candidate

    # If we reach here, k was out of bounds – this shouldn't happen because of the guard
    return None
```

### Correctness Proof  

We prove that the algorithm returns the k‑th smallest element of the union `A ∪ B` of the two sorted arrays `a` and `b`.

---

#### Lemma 1  
During the *main loop* (`while i < m and j < n and count < k`) the variable `candidate` is the next smallest element that has not yet been counted.

*Proof.*  
Because `a` and `b` are sorted, the smallest unexamined element in `A` is `a[i]` (if `i < m`) and the smallest in `B` is `b[j]` (if `j < n`).  
The algorithm compares these two and picks the smaller one (`candidate`).  
Thus `candidate` is the smallest element among all elements that have not yet been examined. ∎



#### Lemma 2  
When the algorithm terminates, `count == k` and the element returned (`candidate`) is the k‑th smallest element of `A ∪ B`.

*Proof.*  
The loop invariant states that after each iteration, `count` equals the number of elements seen so far, and these are the `count` smallest values in `A ∪ B`.  
By Lemma&nbsp;1 the algorithm always picks the next smallest element; the next `candidate` is therefore the `(count+1)`‑th smallest element, so after incrementing `count` the invariant holds.  
When `count == k`, the most recent `candidate` is the `k`‑th smallest value.  
The algorithm returns `candidate` immediately after that increment, hence it returns the correct value. ∎



#### Lemma 3  
If the code reaches the *secondary loops* (`while i < m` or `while j < n`) after the main loop, the element returned is the k‑th smallest.

*Proof.*  
When either `i == m` or `j == n` the main loop terminates.  
At that point every element taken from the exhausted list has been counted, and `count` is the number of elements that have already been examined from the two lists combined.  
Because the invariant still holds, the remaining elements (`a[i:]` or `b[j:]`) are already sorted.  
Therefore the *next* element in the remaining list is exactly the `count+1`‑st smallest, which by the same argument as in Lemma&nbsp;2 gives the `k`‑th smallest when `count` eventually reaches `k`. ∎



#### Theorem  
`kth_smallest(a, b, k)` returns the `k`‑th smallest element among all elements of `a` and `b` (1‑based), if `1 ≤ k ≤ len(a)+len(b)`.

*Proof.*  
By Lemma&nbsp;1, the main loop always picks the smallest remaining element, and the implicit invariant holds for the number of elements processed.  
By Lemma&nbsp;2 the main loop causes the correct element to be returned when `count == k`.  
If the main loop finishes because one list is exhausted, the secondary loops preserve the invariant (Lemma&nbsp;3) and again return the correct element after `count == k`.  
All code paths that succeed in returning an element have returned the k‑th smallest element, proving correctness. ∎

### Complexity Analysis  

Let `k' = min(k, m + n)` be the smaller of the target rank and the total number of elements.  
* Time: Each iteration examines at most one element from either array, so at most `k'` iterations are executed → `O(k')`.  
  In the worst case (`k = m+n`) the runtime is `O(m+n)` – linear in the input size.  
* Space: Only a handful of integer variables are used → `O(1)` auxiliary space.
