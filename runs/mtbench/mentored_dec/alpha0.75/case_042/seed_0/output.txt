Below is a straightforward, well‑documented routine that returns the median of two sorted arrays `a` and `b` that may have different lengths.  
The idea is to *simulate* the merge step of merge‑sort but stop as soon as we hit the required middle element(s).  
No auxiliary arrays are created – only a handful of integer variables – so the space consumption is **O(1)**.  
The running time is bounded by the number of elements we actually inspect; at most `n` elements (`n` = `len(a)+len(b)`), thus **O(n)**.

```java
import java.util.Arrays;

public class MedianOfTwoSortedArrays {

    /**
     * Returns the median of the two sorted arrays `a` and `b`.
     *
     * @param a first sorted array, may be empty
     * @param b second sorted array, may be empty
     * @return median (a double: the exact average in even‑length cases)
     * @throws IllegalArgumentException if both arrays are empty
     */
    public static double medianOfTwoSortedArrays(int[] a, int[] b) {
        // Quick overflow‑safe length check
        long totalLen = (long) a.length + (long) b.length;

        if (totalLen == 0) {                     // both arrays empty
            throw new IllegalArgumentException("Both arrays are empty");
        }

        // The number of elements we must traverse in the virtual
        // merged list to reach the median.
        // In the odd case we need the middle element; in the even case
        // we need the two middle elements.
        int midIndex = (int) (totalLen / 2);            // 0‑based
        int needFirst = (int) (totalLen % 2 == 0 ? midIndex : midIndex); // for even/odd separately
        int needSecond = (int) (totalLen % 2 == 0 ? midIndex - 1 : midIndex); // only used when even

        int i = 0;      // index in array a
        int j = 0;      // index in array b
        int steps = 0;  // how many elements we have taken from the merged stream

        int current = 0;   // current element
        int prev = 0;      // previous element (needed only when even)

        // Single pass over the merged list – we stop after we have identified
        // the middle element(s).  At most we touch all elements.
        while (i < a.length || j < b.length) {
            // Decide which array contains the next smallest element
            if (i < a.length && (j >= b.length || a[i] <= b[j])) {
                current = a[i++];
            } else {
                current = b[j++];
            }

            // When we are at the first of the middle positions we keep
            // the previous element for the even‑case average.
            if (steps == needFirst) {
                prev = current; // this is the point we want to store
            }

            if (steps == needSecond) {
                // Even length — we now have the two middle numbers.
                return (prev + current) / 2.0;
            }

            // In odd case we we are done when `steps == midIndex`
            if (steps == midIndex && totalLen % 2 == 1) {
                return current;
            }
            steps++;
        }

        // Fallback – theoretically unreachable because we already handle both
        // cases inside the loop.  But the compiler needs a return statement.
        throw new IllegalStateException("Unexpected end of array traversal");
    }

    /** Demo & quick tests */
    public static void main(String[] args) {
        int[] a = {1, 3, 5};
        int[] b = {2, 4, 6, 8};

        System.out.println("Median: " + medianOfTwoSortedArrays(a, b)); // 4.5
    }
}
```

### Why this works
1. **Merging with two pointers** – The algorithm keeps two indices (`i` and `j`) that walk through the input arrays just like the merge step of Merge‑Sort.  We only keep the current element chosen and the previous element when needed.

2. **Stopping early** – We only traverse the merged array until we have seen the middle element(s).  The “loop condition” checks for `i < a.length || j < b.length` and the internal `steps` counter decides when to terminate.

3. **Even vs. odd length** –  
   * When the total length is odd, the median is the element at position `midIndex`.  
   * When the total length is even, we need the two middle elements (`midIndex` and `midIndex-1`).  We store the previous element (`prev`) and the current element (`current`) to compute their average.

4. **Space** – We use only a handful of integer variables.  There is no temporary array of length `a.length + b.length`.

5. **Time** – Each element from the two arrays is examined at most once, so the total number of comparisons is `O(n)`.

### Edge cases handled
- One or both arrays may be empty – we only throw an exception if both are empty.
- Duplicate values – no special case needed; the algorithm handles duplicates correctly.
- Size overflow – `totalLen` is calculated as a `long` to avoid overflow when `a.length` or `b.length` are near `Integer.MAX_VALUE`.

def median_two_sorted_arrays(a, b):
    total_len = len(a)+len(b)
    if total_len == 0:
        raise ValueError('Both arrays are empty')
    mid = total_len // 2
    i = j = 0
    steps = 0
    prev = cur = 0

    while i < len(a) or j < len(b):
        if i < len(a) and (j >= len(b) or a[i] <= b[j]):
            cur = a[i]
            i += 1
        else:
            cur = b[j]
            j += 1

        if steps == mid:
            if total_len % 2 == 1:               # odd length
                return cur
            prev = cur
        if steps == mid-1 and total_len % 2 == 0:  # even length
            return (prev + cur)/2.0
        steps += 1
