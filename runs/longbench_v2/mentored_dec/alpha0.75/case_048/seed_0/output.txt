The semi–structured multigrid framework does introduce measurable speed‑ups over a pure unstructured multigrid.  
The key reasons are:

1. **Structured kernels are cheaper** – The block–structured layout allows the use of highly‑optimized, stencil‑based kernels (matrix‑vector products, restriction/interpolation, triple‑matrix product) that can be implemented with far less irregular memory access and communication than the generic sparse‑matrix kernels used in a fully unstructured AMG.  
2. **Streaming sparsity and fewer entries** – Because the matrix is divided into independent regions, the coarse‑grid operators contain much less fill‑in than the unstructured counterparts, leading to reduced matrix‑vector multiplication costs and lower memory footprints.  
3. **Reduced communication** – If the grid transfer operators obey the conditions of the theorem (e.g., linear interpolation on uniform interfaces), the coarse‑grid Galerkin construction can be performed entirely locally, so the communication‑heavy triple‑matrix multiply is avoided.  
4. **Experimentally demonstrated gains** – The paper reports roughly a 2× setup‑time reduction for Poisson and a 3× for elasticity, with the solve time per V‑cycle also reduced, even though the implementation still uses the general Trilinos CSR storage.  
5. **Iteration counts stay the same or improve** – The convergence is largely unchanged (or slightly improved) when using the semi‑structured prolongation/restriction, so the quality of the solver does not degrade.

Hence, the semi‑structured multigrid framework can indeed deliver actual performance improvements compared with a pure unstructured multigrid approach.
