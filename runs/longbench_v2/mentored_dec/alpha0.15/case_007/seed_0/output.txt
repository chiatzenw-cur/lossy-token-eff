We must recall the differences described in the two papers. Jump Over ASLR: The original paper "Jump Over ASLR: Attacking branch predictors to bypass ASLR" authors Evtyushkin, Ponomarev, Abu-Ghazaleh. In that approach, they recover kernel ASLR by layering branch instruction collisions between user and kernel. They use a user-level spy process that intentionally runs a jump instruction at a fixed address and time measured using RDTSC. They create collisions by aligning to addresses and causing BTB to be hit or miss, which changes execution time of the spy. So they infer collisions by measuring execution times of the jump instruction code block. They also switch victim. They test many addresses. They recover branch offset bits.

In the Jump Over ASLR they don't use cache but BTB via timing: a timer measurement of the execution time of a jump instruction in the spy. So they measure the time to execute the jump block. That reveals collisions when the target is the same. That is like the SDC (Same-domain collisions). They do the approach by measuring time difference of executing a code block with a single jump between two targets. So answer likely mentions measuring execution time.

BunnyHop-Reload: The later paper "BunnyHop: Exploiting the Instruction Prefetcher". They propose a technique that uses instruction prefetcher as a covert channel. They exploit BTB collisions by using a flush+reload approach: They evict a target from cache and then check if it's prefetched. They use the fact that when BTB predicts a branch, the prefetcher loads the target into cache. So they can use a flush+reload to see if the target is cached, which indicates the victim branched. So they infer collisions by checking whether the target is cached.

Thus differences: Jump Over ASLR infers collisions by timing execution of jump (execution time measurement), while BunnyHop-Reload infers collisions by detecting target prefetched into the cache via flush+reload.
