Let’s recap each attack:

1. Fork the Jump Over ASLR paper: They defined a side-channel via BTB collisions between user and kernel branches (cross-domain collision or CDC). The attacker builds a timeline: They use a known branch instruction in kernel, plus a branch instruction in attacker code. They rely on the fact that BTB tags use only lower bits of address, ignoring higher bits. So collisions can happen between kernel and user branch if addresses match in lower bits. They perform **timing measurement** of the spy’s execution when its branch instruction might collide with victim's branch. They generate collisions by executing the victim's system call, so the kernel branch is recorded. They then scan through potential addresses where target may be located. They measure execution time of the spy's branch instruction (which has a jmp instruction). A collision results in a slowdown because of a mispredicted branch. They use cycle counts to find an address with higher execution time, indicating collision. So it's a timing side-channel based on measuring the execution time of the jump instruction or code block.

They also used collisions between two user processes, for user-level ASLR. Similar approach: use same concept: measure execution time of spy process over code that includes a branch instruction. The collisions cause slowdown due to BTB misprediction. That is the timing channel.

So Jump Over ASLR infers collisions basically by measuring the execution time (latency) of the branch instruction execution in spy process.

2. BunnyHop-Reload: They use the instruction prefetcher, which prefetches target addresses of predicted branches into caches. The idea: The branch predictor holds branch target information. When a branch instruction is executed, the instruction prefetcher may prefetch the target block if the branch is predicted. The custom BunnyHop technique works like a Flush+Reload but for BTB: The attacker flushes a target address from cache, then executes a NOP near a branch instruction that will cause prefetch to load the target. If target is prefetched, reload reveals cache hit. Alternatively, in BunnyHop-Reload, attacker evicts the BTB entry for branch (prevents victim from prefetching). Then wait for victim to run. Then execute a piece containing a NOP at an aliased address; if victim executed the branch, prefetcher will prefetch target; attacker uses Flush+Reload to check if target was prefetched into the cache. So difference is that Jump Over ASLR uses execution time measurement to detect collisions, while BunnyHop‑Reload uses the prefetcher state (cache presence) to detect collisions.
