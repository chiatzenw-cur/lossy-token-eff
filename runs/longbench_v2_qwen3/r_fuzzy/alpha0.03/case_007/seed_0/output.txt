---

### **1. Jump Over ASLR**
- **Objective**: To bypass ASLR by exploiting **BTB collisions** between a user-level process and the kernel. 
- **Method**: The attacker creates **collisions** in the BTB between a user branch and a kernel branch (e.g., via **cross-domain collisions**). These collisions cause **timing variations** in the execution of code due to the BTB's internal state. 
- **Key Insight**: The attacker **measures the execution time** of certain code blocks (e.g., those involving NOPs) to detect whether a collision occurred. A **longer execution time** indicates that the BTB entry was **overwritten** and thus a collision occurred.
- **Focus**: This technique relies on **timing differences** caused by **BTB state changes**, which affect the execution path of the victim's code.

---

### **2. BunnyHop-Reload**
- **Objective**: To **reconstruct the BTB's state**, including its **target addresses** and **associativity**, by exploiting the **instruction prefetcher**.
- **Method**: 
  - The attacker **evicts** a specific BTB entry from the cache.
  - They then **measure** whether the entry is **reloaded** (i.e., whether the target is **prefetched** into the cache) after the victim executes a branch. 
  - This is done using **Flush+Reload**-like timing: if the target is **cached**, it means the victim **executed** the branch, and thus the **BTB state** has changed.
- **Key Insight**: Rather than measuring execution time directly, **BunnyHop-Reload** **checks whether a specific target address is prefetched** (cache remotely accessible) to infer if the branch was taken. This **indirectly reveals** BTB collisions.

---

### **Key Differences**
- **Jump Over ASLR** focuses on **timing differences** caused by **BTB collisions** and uses **code execution timing** to infer collisions.
- **BunnyHop-Reload** focuses on **cache state changes**, specifically whether a **target address is prefetched**, to **indirectly infer** BTB collisions.
