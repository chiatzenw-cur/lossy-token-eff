### C++ Program to Find the nth Fibonacci Number Using Recursion

Here's a well-structured C++ program that computes the **nth Fibonacci number using recursion**, aligned with the standard **zero-based indexing** for the Fibonacci sequence.

This program uses the standard recursive formula:

$$
\text{Fib}(n) = \text{Fib}(n-1) + \text{Fib}(n-2) \quad \text{for } n > 1
$$
with:
- $\text{Fib}(0) = 0$
- $\text{Fib}(1) = 1$

Both recursion and input handling are included in the final implementation.

---

### ✅ **Code:**

```cpp
#include <iostream>
using namespace std;

// Function to compute the nth Fibonacci number using recursion
int fibonacci(int n) {
    if (n <= 1) {
        return n;
    } else {
        return fibonacci(n - 1) + fibonacci(n - 2);
    }
}

int main() {
    int n;

    // Ask the user for input
    cout << "Enter the value of n: ";
    cin >> n;

    // Check for invalid input (negative number)
    if (n < 0) {
        cout << "Error: Please enter a non-negative integer." << endl;
        return 1;
    }

    // Display the result
    cout << "The nth Fibonacci number is: " << fibonacci(n) << endl;

    return 0;
}
```

---

### 📌 **Explanation:**

- **Recursive Function:** The `fibonacci` function recursively computes the value by summing the two previous numbers in the sequence.
- **Base Case:** `if (n <= 1)` returns `n` directly, which handles `Fib(0) = 0` and `Fib(1) = 1`.
- **Input Handling:** The main function includes input validation to reject negative integers by printing an error message.
- **Output:** The result is printed with an appropriate message.

---

### 🧪 **Example Cyphers:

If the user enters:
- `n = 5` → Output: `5` (Fibonacci sequence: 0, 1, 1, 2, 3, 5)
- `n = 0` → Output: `0` (Fibonacci sequence starts with 0)
- `n = 10` → Output: `55`

### ⚠️ **Note Thought:**

While this recursive implementation is valid, it’s important to note that it’s **not efficient** for large `n` due to the exponential complexity of repeated recursive calls. For practical use cases with larger values, to use **iterative** or **memoization** techniques (like dynamic programming) could be more efficient.
