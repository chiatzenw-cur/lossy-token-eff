To find the **majority element** in an array using the **Boyer-Moore Voting Algorithm**, we follow a systematic and efficient approach that guarantees to identify the candidate element that appears more than half the time in the array (i.e., the majority element), assuming such an element exists.

---

### ✅ **Understanding the Algorithm**

The Boyer-Moore Voting Algorithm is based on the following key idea:

- Traverse the array while maintaining a **candidate** and a **count**.
- If the count is zero at any step, set the current element as the new candidate.
- For each element:
  - If it matches the candidate, increment the count.
  - Otherwise, decrement the count.
- At the end of the traversal, the **candidate** is the majority element (if it exists).

This method runs in **O(n)** time and uses **O(1)** space, which is efficient.

---

### 🧠 **Why This Works**

- The algorithm leverages the principle that if a majority element exists, it will "outvote" all other elements in the voting process, ensuring it ends up as the final candidate.
- Even when there is **no majority element**, the candidate returned by the algorithm may be incorrect. However, **in the context of this problem**, we assume that the input array **contains a majority element** (i.e., one that appears more than `n/2` times), and thus the algorithm will correctly return it.

---

### 🧾 **Python Implementation**

```python
def majority_element(nums):
    candidate = None
    count = 0

    for num in nums:
        if count == 0:
            candidate = num
        if num == candidate:
            count += 1
        else:
            count -= 1

    return candidate
```

---

### 🎯 Example Use Case

```python
nums = [2, 2, 1, 1, 2, 2, 3]
print(majority_element(nums))  # Output: 2
```

**Explanation:**

- The element `2` appears 4 times, which is more than half (7/2 = 3.5) of the length of the array.
- The algorithm correctly identifies it as the majority element.

---

### 🧪 Notes & Assumptions

- The function assumes that a **majority element exists** in the input array.
- If there's **no majority element**, the final candidate may be incorrect. However, this is an edge case and not checked here due to the nature of the algorithm.
- If verification is required, you could perform a second pass to count occurrences of the candidate and ensure it meets the majority condition (i.e., count > len(nums) // 2).
